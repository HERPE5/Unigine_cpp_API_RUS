# Application Logic System


В зависимости от API, выбранного при [creating a project](../../../sdk/projects/index_cpp.md#application_settings), вы можете реализовать логику вашего приложения на **C++** или **C#**. Это основные и рекомендуемые языки для разработки приложений в UNIGINE.


Кроме того, вы можете комбинировать **C++/C#** с **UnigineScript**, реализуя определённые части логики в скриптах `*.usc`.


Если реализованы методы и C++/C#, и UnigineScript, порядок выполнения следующий:


- метод UnigineScript
- метод C++/C#


> **Предупреждение:** Область применения UnigineScript ограничена реализацией логики, связанной с материалами (material expressions, scriptable materials, brush materials). Доступность новых функций движка в UnigineScript (за пределами его области применения) не гарантируется, так как текущий уровень поддержки предполагает только исправление критических проблем.
>
>
> Хотя технически вы можете полностью построить проект на UnigineScript, **такой подход не рекомендуется**. Используйте C++ или C# для общей логики приложения.


## Структура логики приложения


Логика приложения в UNIGINE определяется через набор методов жизненного цикла, предоставляемых движком. Эти методы группируются по разным типам логики и вызываются на определённых этапах последовательности выполнения.


Реализуя их, вы определяете поведение вашего приложения во время загрузки мира, запуска системы, событий редактора и так далее.


Логика приложения в UNIGINE определяется в нескольких контекстах, каждый из которых имеет свой жизненный цикл и назначение:


- **[World Logic](#worldlogic)** выполняется только когда загружен мир. **[Component System](../../../principles/component_system/index.md)** - модульные строительные блоки для логики приложения. Component System доступна только для проектов на **C++** и **C#**. Она позволяет реализовать логику вашего приложения через набор строительных блоков - **компонентов**, и назначать эти блоки узлам, придавая им дополнительную функциональность. Комбинируя эти маленькие и простые блоки, можно создать очень сложную систему логики. > **Примечание:** [Component System](../../../principles/component_system/index.md) также основана на классе WorldLogic (наследуется от него). В результате все компоненты предоставляют те же методы жизненного цикла, что и WorldLogic (такие как *init()*, *update()*, *updatePhysics()* и т.д.).

  - Логика мира на **C++/C#** реализуется путём наследования от класса *[WorldLogic](../../../api/library/common/logic/class.worldlogic_cpp.md)*. По умолчанию движок генерирует `AppWorldLogic.cpp` или `AppWorldLogic.cs` в директории *source/* вашего проекта. В отличие от UnigineScript, логика мира на C++/C# остаётся загруженной на протяжении всего времени работы движка и применяется ко всем мирам, поэтому её нельзя назначить конкретному миру.
  - Логика мира на **UnigineScript** реализуется в файле скрипта мира (`*.usc`). Каждый мир может иметь собственный скрипт, а скрипт по умолчанию автоматически создаётся при создании нового проекта на UnigineScript - он называется по имени проекта и хранится в папке `data/`.
- **[System Logic](#systemlogic)** существует на протяжении всего жизненного цикла приложения, независимо от загруженного мира. Она активна, когда мир не загружен, во время переходов между мирами и пока мир работает. Используйте системную логику для задач, которые должны сохраняться независимо от какого-либо конкретного мира (например, глобальное состояние приложения или GUI) > **Примечание:** Скрипт `unigine.usc`, содержащий шаблон системной логики, создаётся по умолчанию для всех типов проектов. Вы можете убедиться в этом, проверив вывод консоли при запуске редактора или движка: > ```text > 						---- Interpreter ---- > Version: 2.90 > > Unigine~# config_autosave 1 && world_load "UnigineProject" > Script loading "core/unigine.usc" 11ms									<- System Script is loaded > World loading "UnigineProject.world" (Time: 31.6ms, Memory: 0B) > > ``` > > > Системная логика UnigineScript (`unigine.usc`) в основном предназначена для внутренней функциональности движка. Хотя её всё ещё можно использовать, полагаться на неё при разработке на C++/C# не рекомендуется.

  - Системная логика на **C++/C#** реализуется путём наследования от класса *[SystemLogic](../../../api/library/common/logic/class.systemlogic_cpp.md)*. По умолчанию исходный файл (`AppSystemLogic.cpp` или `AppSystemLogic.cs`) генерируется в директории *source/* вашего проекта.
  - Системная логика на **UnigineScript** реализуется в системном скрипте по умолчанию `unigine.usc`, который хранится в папке data/ внутри архива core.ung. Вы можете разместить свою пользовательскую логику прямо в этом файле.
- **[Editor logic](#editorlogic)** Этот тип логики используется в случае, если вам нужно реализовать собственный редактор. У него больше реализованных методов, дающих чёткое понимание текущих событий движка (узел был создан, свойство было удалено, материал был изменён и т.д.). <details> <summary>Show | Close</summary> *editor.usc* ```text #include <editor2/editor_tracker.h> #include <editor2/editor_video_grabber.h> int init() { return 1; } int update() { return 1; } int shutdown() { return 1; } ``` </details>

  - Логика редактора на **C++/C#** определяется путём наследования от класса *[EditorLogic](../../../api/library/common/logic/class.editorlogic_cpp.md)*.
  - Логика редактора на **UnigineScript** по умолчанию загружается из файла `editor2/editor.usc`, хранящегося внутри `editor2.ung`. Вы можете переопределить этот файл логики UnigineScript, создав папку с именем `editor2` в вашей папке `data` и поместив туда файл `editor.usc` со следующим кодом (вы можете изменять этот скрипт, но не удаляйте существующие строки *include*, так как они необходимы для работы редактора):


> **Примечание:** При создании нового проекта на C++/C# он уже наследует класс World Logic (*AppWorldLogic*) и класс System Logic (*AppSystemLogic*) с реализованными методами, куда вы можете поместить код своей логики.
>
>
> Однако вы также можете реализовать собственную логику, унаследовавшись от базовых классов и зарегистрировав её во время выполнения движка.


## Логика мира


Логика мира работает немного по-разному в зависимости от реализации:


- Если World Logic реализована на C++ или C#, она остаётся загруженной, пока загружен любой мир.
- Если реализована на UnigineScript, она загружается и выгружается вместе с самим миром.
- В случае Component System время жизни определяется каждым компонентом индивидуально.


World Logic может использовать следующие методы, доступные как для C++/C#, так и для UnigineScript:

### Метод init()


Движок вызывает этот метод при инициализации мира. Код внутри должен инициализировать ресурсы для вашей сцены мира во время запуска мира.


### Метод updateAsyncThread()


В методе *updateAsyncThread()* вы можете указать все методы логики, которые должны вызываться каждый кадр независимо от потока рендеринга. Этот метод не блокирует главный поток. Однако кадр синхронизируется на границе: движок ждёт завершения updateAsyncThread() перед началом следующего кадра (ожидание происходит во время swap()), поэтому превышение бюджета кадра здесь всё равно задержит следующий кадр.


> **Примечание:** Этот метод не имеет защитных блокировок, поэтому не рекомендуется изменять другие компоненты внутри этого метода, если вы не абсолютно уверены, что эти компоненты не будут изменены или удалены где-либо ещё.


### Метод updateSyncThread()


В методе *updateSyncThread()* вы можете указать любые параллельные функции логики, которые должны выполняться перед *Update()*. Этот метод **блокирует главный поток** до завершения всех вызовов.


> **Примечание:** Этот метод следует использовать только для вызова методов API, связанных с текущим узлом: сам узел, его материалы и свойства.


### Метод update()


В методе *update()* вы можете указать все функции, связанные с логикой, которые должны вызываться каждый кадр во время выполнения вашего приложения. Движок вызывает этот метод перед обновлением каждого кадра рендеринга.


### Метод postUpdate()


Это дополнительный метод, используемый для корректировки поведения после обновления состояния узла. Движок вызывает этот метод перед рендерингом каждого кадра рендеринга.


### Метод updatePhysics()


Этот метод используется для управления физикой в вашем приложении. Движок вызывает этот метод перед обновлением каждого кадра физики.


### Метод swap()


Этот метод предназначен для работы с результатами метода *updateAsyncThread()* — все остальные методы (потоки) уже выполнены и простаивают.


### Метод shutdown()


Метод вызывается при выгрузке мира (или удалении компонента) и используется для освобождения любых ресурсов, выделенных во время выполнения мира или компонента, чтобы избежать утечек памяти.


> **Примечание:** Базовый рекомендуемый рабочий процесс - иметь один класс *AppWorldLogic* для обработки всех миров в вашем проекте. Однако вы можете [split world-specific code between separate classes](../../../code/usage/multiple_worldlogic/index_cpp.md), унаследованными от *[WorldLogic](../../../api/library/common/logic/class.worldlogic_cpp.md)*.


## Системная логика


System Logic остаётся загруженной на протяжении всего времени работы движка UNIGINE. Она может использовать следующие методы, доступные как для C++/C#, так и для UnigineScript:


<details>

```cpp

AppSystemLogic::AppSystemLogic() {

}

AppSystemLogic::~AppSystemLogic() {

}

int AppSystemLogic::init() {
	return 1;
}

int AppSystemLogic::update() {
	return 1;
}

int AppSystemLogic::postUpdate() {
	return 1;
}

int AppSystemLogic::shutdown() {
	return 1;
}


```

</details>


### Метод init()


Движок вызывает этот метод при инициализации. Здесь следует разместить код, который должен выполняться во время инициализации системного скрипта.


### Метод update()


Движок вызывает этот метод перед обновлением каждого кадра рендеринга. Здесь следует разместить код, который должен обновляться каждый кадр. Логика должна быть связана с работой движка. Вот примеры операций, выполняемых системным скриптом по умолчанию:


- Системный скрипт обрабатывает мышь. Он контролирует, захватывается ли мышь при клике (по умолчанию), исчезает ли курсор мыши при отсутствии движения в течение некоторого времени, или не обрабатывается системой.
- Обновляется логика главного меню.
- Обрабатывается другой пользовательский ввод, связанный с системой.


### Метод postUpdate()


Движок вызывает этот метод перед рендерингом каждого кадра рендеринга. Он может получить доступ к обновлённым данным о состояниях узлов и соответствующим образом скорректировать поведение в том же кадре.


### Метод shutdown()


Движок вызывает этот метод при завершении работы приложения. Вам следует освободить все ресурсы, созданные для системного скрипта.


## Логика редактора


Этот компонент используется в случае, если вам нужно реализовать собственный редактор. У него больше реализованных методов, дающих чёткое понимание текущих событий движка (узел был создан, свойство было удалено, материал был изменён и т.д.).


Editor Logic может использовать следующие методы, доступные как для C++/C#, так и для UnigineScript:

```cpp
}

AppEditorLogic::~AppEditorLogic() {

}

int AppEditorLogic::init() {
	return 1;
}

int AppEditorLogic::update() {
	return 1;
}

int AppEditorLogic::postUpdate() {
	return 1;
}

int AppEditorLogic::shutdown() {
	return 1;
}

int AppEditorLogic::worldInit() {
	return 1;
}

int AppEditorLogic::worldShutdown() {
	return 1;
}

int AppEditorLogic::worldSave() {
	return 1;

```

</details>


### Метод init()


Движок вызывает этот метод при инициализации мира. Он инициализирует все компоненты UnigineEditor.


### Метод update()


Если редактор загружен, движок вызывает этот метод перед обновлением каждого кадра рендеринга. Здесь можно разместить логику, связанную с редактором, которая должна обновляться каждый кадр.


### Метод postUpdate()


Если редактор загружен, движок вызывает этот метод перед рендерингом каждого кадра рендеринга.


### Метод shutdown()


Движок вызывает этот метод при завершении работы редактора. Приложения движка могут продолжать работать.


### Метод render()


Движок вызывает этот метод перед рендерингом каждого кадра рендеринга для указанного окна движка, когда редактор загружен. Здесь, например, можно выполнить произвольный рендеринг для ваших инструментов редактора.


### Метод worldInit()


Если редактор загружен, движок вызывает этот метод при инициализации мира. Используйте этот метод, если хотите инициализировать что-либо до того, как World Logic запустит свою функцию *[init()](#worldlogic_init)*.


### Метод worldShutdown()


Если редактор загружен, движок вызывает этот метод при выгрузке мира.


### Метод worldSave()


Если редактор загружен, движок вызывает этот метод при сохранении мира.
