# Where to Put Your Code


Чтобы придать вашему миру интерактивность и поведение, вам нужно определить логику, которая им управляет.


Ваш код можно разместить в предопределённых частях [application logic system](../../../code/fundamentals/execution_sequence/app_logic_system.md) - движок автоматически вызовет соответствующие методы согласно [execution sequence](../../../code/fundamentals/execution_sequence/index.md). Кроме того, движок поддерживает обширную систему событий, позволяющую обрабатывать различные события, которые могут произойти в любой момент во время выполнения.


[World Logic](../../../code/fundamentals/execution_sequence/app_logic_system.md#world_logic) имеет набор функций, используемых для реализации логики приложения.


- Функция [Initialization](../../../code/fundamentals/execution_sequence/init.md) World Logic (***init()***) используется для создания объектов и инициализации всех остальных необходимых ресурсов при загрузке мира.
- Функция [Shutdown](../../../code/fundamentals/execution_sequence/shutdown.md) (***shutdown()***) вызывается при выгрузке мира и используется для удаления ресурсов, созданных во время выполнения логики, чтобы избежать утечек памяти.


Тот же набор методов применяется к компонентам, так как Component System является частью WorldLogic, хотя их поведение немного отличается:


- Метод ***init()*** каждого компонента вызывается во время инициализации компонента, что происходит в момент прикрепления компонента к узлу.
- Метод ***shutdown()*** каждого компонента вызывается при удалении компонента или уничтожении узла, к которому прикреплён этот компонент.


А как насчёт покадрового обновления? И [World Logic](../../../api/library/common/logic/class.worldlogic_cpp.md) (AppWorldLogic.cs или AppWorldLogic.cpp), и [Components](../../../principles/component_system/index.md) предоставляют набор методов, обеспечивающих покадровую обработку логики приложения:


- *[updateAsyncThread()](#code_updateAsyncThread)* может содержать функции логики, которые должны вызываться каждый кадр независимо от потока рендеринга: поиск пути, генерация процедурных текстур, пользовательская физика и т.д.
- *[updateSyncThread()](#code_updateSyncThread)* может содержать любые параллельные функции логики, выполняемые перед *update()*.
- *[update()](#code_update)* может содержать любую логику: управление тем, что рендерить на экране и как это делать, рендеринг в текстуры, создание узлов, вызов консольных команд и т.д.
- *[updatePhysics()](#code_updatePhysics)* можно использовать для симуляции физики: выполнения непрерывных операций (толкание машины вперёд в зависимости от текущих оборотов двигателя, симуляция постоянно дующего ветра, выполнение немедленной реакции на столкновение и т.д.).
- *[postUpdate()](#code_postUpdate)* можно использовать для коррекции поведения в соответствии с обновлёнными состояниями узлов в том же кадре.
- *[swap()](#code_swap)* можно использовать для обработки результатов функции *[updateAsyncThread()](#code_updateAsyncThread)*.


> **Примечание:** В отличие от World Logic, которая привязана к миру, System Logic работает на уровне приложения и включает похожий набор методов: init(), shutdown(), update(), postUpdate().


В дополнение к стандартным методам жизненного цикла и покадрового обновления, компоненты включают несколько уникальных callback-функций, расширяющих их функциональность:


- [*OnReady()*](../../../api/library/common/logic/component_system/cs/class.component.md#on_ready_void) для C# или [*on_ready()*](../../../api/library/common/logic/component_system/cpp/class.componentbase_cpp.md#on_ready_void) для C++ - вызывается **немедленно** после того, как компонент был создан и прикреплён к узлу.
- [*OnEnable()*](../../../api/library/common/logic/component_system/cs/class.component.md#on_enable_void) для C# или [*on_enable()*](../../../api/library/common/logic/component_system/cpp/class.componentbase_cpp.md#on_enable_void) для C++ - вызывается **немедленно**, когда компонент становится включённым (и узел, и свойство активны).
- [*OnDisable()*](../../../api/library/common/logic/component_system/cs/class.component.md#on_disable_void) для C# или [*on_disable()*](../../../api/library/common/logic/component_system/cpp/class.componentbase_cpp.md#on_disable_void) для C++ - вызывается **немедленно**, когда компонент становится отключённым (и узел, и свойство отключены).


## Code UpdateAsyncThread


В ***updateAsyncThread()*** логики мира вы можете указать все функции логики, которые должны вызываться каждый кадр независимо от потока рендеринга. Эту функцию можно использовать для выполнения тяжёлых, ресурсоёмких расчётов, выполняемых на протяжении всего кадра, таких как поиск пути, генерация процедурных текстур, пользовательская физика и т.д. Эта функция не блокирует главный поток, однако её завершение ожидается в конце кадра, поэтому долго выполняющихся задач следует избегать.


## Code UpdateSyncThread


В ***updateSyncThread()*** логики мира вы можете указать любые параллельные функции логики, которые должны выполняться перед *[update()](#code_update)*. Эта функция **блокирует главный поток** до завершения всех вызовов.


Эту функцию можно использовать для выполнения тяжёлых, ресурсоёмких расчётов, таких как поиск пути, генерация процедурных текстур, манипуляции с большими объёмами данных, результат которых требуется до начала рендеринга кадра. Эту функцию также можно использовать для более простых операций, которые можно реализовать в функции *[update()](#code_update)*, чтобы распределить их между потоками и повысить производительность.


## Code Update


В ***update()*** логики мира вы можете разместить все функции, которые должны вызываться каждый кадр во время выполнения вашего приложения. Она служит для реализации любой логики. Коротко говоря, изнутри *update()* можно управлять множеством вещей (связанных с графикой или нет). Здесь вы можете:


- Создавать и удалять узлы.
- [Move](../../../api/library/nodes/class.node_cpp.md#setPosition_Vec3_void) узлы по сцене и [rotate](../../../api/library/nodes/class.node_cpp.md#setRotation_quat_int_void) их.
- Изменять любые параметры узлов.
- Симулировать [particle systems](../../../api/library/objects/class.objectparticles_cpp.md).
- Управлять [skinned animation](../../../api/library/objects/class.objectmeshskinned_cpp.md).
- Устанавливать глобальные [rendering settings](../../../api/library/rendering/class.render_cpp.md).
- Создавать и манипулировать вашим [GUI](../../../api/library/gui/class.gui_cpp.md).
- [Render to textures](../../../api/library/rendering/class.viewport_cpp.md).
- Выполнять команды [console](../../../api/library/engine/class.console_cpp.md).
- Даже выполнять некоторую физику — совершать мгновенные действия: добавлять [impulses](../../../api/library/physics/class.bodyrigid_cpp.md#addImpulse_vec3_vec3_void), симулировать удар или толчок, устанавливать [linear](../../../api/library/physics/class.bodyrigid_cpp.md#setLinearVelocity_vec3_void) или [angular velocity](../../../api/library/physics/class.bodyrigid_cpp.md#setAngularVelocity_vec3_void), добавлять или удалять [shapes](../../../api/library/physics/class.shape_cpp.md) и [joints](../../../api/library/physics/class.joint_cpp.md), и изменять их параметры.


> **Примечание:** Не применяйте [forces](../../../api/library/physics/class.bodyrigid_cpp.md#addForce_vec3_vec3_void) и [torques](../../../api/library/physics/class.bodyrigid_cpp.md#addTorque_vec3_void) к твёрдым телам в *update()*. Иначе вы получите нестабильный результат, изменяющийся с каждым кадром рендеринга. Все непрерывные операции должны выполняться внутри *[*updatePhysics()*](#code_updatePhysics)*.


## Code UpdatePhysics


Функция ***updatePhysics()*** логики мира в основном используется для управления физикой в вашем приложении. Как правило, эта функция используется для непрерывных операций, таких как толкание машины вперёд в зависимости от текущих оборотов двигателя, симуляция постоянно дующего ветра, выполнение немедленной реакции на столкновение (так как *updatePhysics()* может выполняться несколько раз за один кадр рендеринга, вы можете обрабатывать множественные отскоки объектов при их столкновении друг с другом и отслеживать их, в то время как *update()* покажет нам только конечный результат) и т.д. *updatePhysics()* выполняется в главном потоке, поэтому здесь можно выполнять любые действия так же, как в *update()*:


- Работать со всеми физическими [bodies](../../../principles/physics/bodies/index.md) и [shapes](../../../principles/physics/shapes/index.md).
- Применять [forces](../../../api/library/physics/class.bodyrigid_cpp.md#addForce_vec3_void), [impulses](../../../api/library/physics/class.bodyrigid_cpp.md#addImpulse_vec3_vec3_void) и [torques](../../../api/library/physics/class.bodyrigid_cpp.md#addTorque_vec3_void) к [rigid bodies](../../../principles/physics/bodies/rigid/index.md).
- Создавать, прикреплять или разрывать [joints](../../../api/library/physics/class.joint_cpp.md), а также изменять их параметры.
- Создавать и манипулировать [shapes](../../../api/library/physics/class.shape_cpp.md) и изменять их параметры.
- Создавать и настраивать [physicals](../../../objects/effects/physicals/index.md).


Вы также можете делать следующее (и многое другое):


- Перемещать и трансформировать узлы, если они включены.
- Создавать новые узлы.
- Удалять узлы.


## Code PostUpdate


Функция ***postUpdate()*** логики мира - это дополнительная функция, используемая для коррекции поведения после обновления состояния узла (например, скелетная анимация была проиграна в текущем кадре или система частиц породила свои частицы).


Представьте ситуацию, когда нам нужно прикрепить объект (скажем, меч) к руке скелетного персонажа. Если мы получим трансформацию кости руки персонажа и установим её мечу в функции *[*update()*](#code_update)*, крепление будет неточным, а не точным. Меч не будет плотно удерживаться в руке, потому что анимация фактически проигрывается сразу после выполнения *update()* логики мира. Это значит, что трансформации костей, возвращённые в *update()*, будут относиться к предыдущему кадру. *postUpdate()* логики мира выполняется после проигрывания анимации, а значит, вы можете получить обновлённые трансформации костей для текущего кадра изнутри этой функции и установить их мечу.


> **Примечание:** Используйте *postUpdate()* только для целей коррекции; в противном случае это увеличит время главного цикла. Все остальные функции следует размещать внутри *[update()](#code_update)* или *[updatePhysics()](#code_updatePhysics)* (физика).


## Code Swap


Движок вызывает эту функцию после завершения следующих процессов: рендеринг (часть CPU), расчёты физики и поиск пути, рендеринг GUI, а также все асинхронные потоки. Функция предназначена для обработки результатов метода *[updateAsyncThread()](#code_updateAsyncThread)* — все остальные методы (потоки) уже выполнены и простаивают. После этой функции происходят только два действия:


- Удаляются все объекты, поставленные в очередь на удаление.
- Обновляется профилировщик.


## Обработчики событий


Вы также можете определять свою логику через callback-функции, вызываемые при возникновении определённых событий в вашем приложении.


Важно отметить, что callback-функции событий не всегда выполняются немедленно. Для некоторых типов событий callback-функции помещаются во внутреннюю очередь выполнения и обрабатываются в следующей запланированной точке выполнения согласно [Execution Sequence](../../../code/fundamentals/execution_sequence/index.md).


Например, [body and joint events](../../../code/fundamentals/events/index_cpp.md#physics) срабатывают в конце обновления физики, в то время как события *[WorldTrigger](../../../objects/worlds/world_trigger/index.md)* и *[NodeTrigger](../../../objects/nodes/trigger/index.md)* вызываются в середине этапа Update. Эти события выполняются в строго определённых точках цикла кадра, так как логика, определённая внутри них, может влиять на рендеринг или другие системы.


Более подробную информацию о событиях движка см. в статье **[Event Handling](../../../code/fundamentals/events/index_cpp.md)**.
