# Procedural Mesh Generation

Этот пример демонстрирует, как генерировать геометрию статических мешей во время выполнения с использованием различных методов процедурной генерации мешей. Создаётся сетка объектов *ObjectMeshStatic*, каждый из которых получает свою геометрию из пользовательского callback, строящего поверхность меша в форме коробки через *Mesh API*.

Вы можете экспериментировать с различными процедурными режимами (такими как *Dynamic, File* или *Blob*), а также настраивать способ хранения и доступа к геометрии, выбирая разные флаги использования MeshRender (только для DirectX 12). Эти флаги определяют, хранятся ли данные вершин и/или индексов в RAM вместо VRAM, позволяя GPU рендерить непосредственно из системной памяти.

-**Dynamic** - самая высокая производительность, хранится в RAM и VRAM, не выгружается из памяти автоматически.
-**Blob** - умеренная производительность, хранится в RAM и VRAM, автоматически выгружается из памяти.
-**File** - самая низкая производительность, все данные хранятся на диске, автоматически выгружаются из памяти.

Параметр **Field Size** определяет, сколько объектов меша генерируется по каждой оси, формируя квадратную сетку.

Для каждой конфигурации пример показывает общее использование RAM и VRAM, а также количество активных объектов меша. Это упрощает оценку производительности, распределения памяти и поведения каждого процедурного режима в различных условиях выполнения.

Используйте этот пример, чтобы понять, как работает процедурная генерация мешей в разных режимах, наблюдать за тем, как геометрия хранится и управляется между RAM, VRAM и диском, профилировать использование памяти для малого и большого количества процедурных объектов, а также изучить, как стратегии обновления влияют на производительность.

Обратитесь к статье Procedural Mesh Workflow для получения дополнительной информации о поведении памяти, стратегиях обновления и рекомендациях при работе с процедурной геометрией.
