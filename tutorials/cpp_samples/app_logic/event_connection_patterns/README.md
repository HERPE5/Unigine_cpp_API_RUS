# Event Connection Patterns

Этот пример демонстрирует четыре различных паттерна подписки на *Events* UNIGINE через C++ API, показывая, как время жизни и управление обработчиками событий могут отличаться в зависимости от подхода.

Каждый метод демонстрирует свою стратегию подключения к одному и тому же событию и управления временем жизни обработчиков событий:

-*EventConnectionExample* хранит один обработчик события с ручным управлением его активацией. Этот тип подключения полезен, когда нужен точный контроль &#8212; вы можете включить, отключить или полностью разъединить обработчик в любой момент.
-*EventConnectionsExample* действует как контейнер для нескольких обработчиков. Он выполняет очистку автоматически (через деструктор) и вручную (вызовом *EventConnections::disconnectAll()*). Это полезно, когда у вас много обработчиков событий с разным временем жизни, которые нужно сгруппировать.
-*InheritedEventConnectionExample* наследует класс *EventConnections*, делая управление подключением частью своей внутренней логики. Все подключённые обработчики автоматически отсоединяются при уничтожении объекта.
-*CallbackIDConnection* предоставляет низкоуровневый, ручной способ управления обработчиками с помощью ID подключения. Он даёт гибкость, но требует тщательной работы с памятью и временем жизни. Этот подход считается небезопасным и должен использоваться только при полном понимании последствий.

Каждый пример подключается к общему *EventHolder*, и обработчики запускаются с примерным значением. Такая настройка полезна при проектировании модульных, реактивных систем, опирающихся на гибкую и явную логику, управляемую событиями.
