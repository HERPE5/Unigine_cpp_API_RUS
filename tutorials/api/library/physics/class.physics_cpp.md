**Header:** #include <UniginePhysics.h>

## UPDATE_MODE

[Physics update mode](../../../principles/physics/simulation.md#update_mode).
| Имя | Описание |
|---|---|
| **UPDATE_MODE_BEFORE_RENDERING** = 0 | Обновление перед рендерингом. Обновление физики (вместе с обновлением пространственного дерева и пользовательскими колбэками) выполняется в главном потоке непосредственно перед выполнением рендеринга (render). Количество тиков физики, выполняемых перед кадром рендеринга, здесь определяется [physics and the Engine framerates](../../../code/fundamentals/execution_sequence/index.md#cape_framerate). Этот режим наиболее понятен и прост (всё выполняется безопасно в строго определённом порядке) без задержки кадра (результаты расчётов физики применяются в текущем кадре). Однако, с другой стороны, этот режим самый медленный, так как отсутствуют асинхронные параллельные вычисления (всё выполняется в главном потоке). Используйте этот режим, если задержка неприемлема для вашего приложения (нужно, чтобы все расчёты физики применялись в текущем кадре) и вам нужны максимальная простота и строго определённый порядок выполнения пользовательского кода (physicsUpdate и колбэки физики). |
| **UPDATE_MODE_ASYNC_RENDERING** = 1 | Асинхронный режим обновления. Обновление физики выполняется асинхронно относительно рендеринга. В случае нескольких тиков физики на один кадр рендеринга (когда частота кадров движка ниже, или выполняется [catching up](../../../principles/physics/simulation.md#catch_up)), только первый выполняется параллельно, затем модуль физики ожидает завершения процесса рендеринга, возвращается в главный поток и выполняет остальные тики физики. Присутствует задержка кадра (результаты расчётов физики применяются в следующем кадре), и есть некоторая неоднозначность относительно момента, когда должен выполняться пользовательский код (physicsUpdate и колбэки физики) в случае нескольких тиков физики на один кадр рендеринга (часть выполняется перед рендерингом, а часть — сразу после него). Этот режим самый быстрый и используется по умолчанию. |

## Ptr < Object > getIntersection ( const Math:: Vec3 & p0 , const Math:: Vec3 & p1 , int mask , const Vector < Ptr < Node > > & exclude , const Ptr < PhysicsIntersection > & intersection )


Выполняет трассировку от точки p0 до точки p1 для поиска объекта столкновения, расположенного на этой линии. Если объекту назначено тело, пересечение выполняется с его формой. Если у объекта нет тела, эта функция определяет пересечение с поверхностями (полигонами) объектов с установленным флагом пересечения. Пересечение находится только для объектов с совпадающей маской, если их ID не найден в списке *exclude*. Пересечение не работает для отключённых объектов.


> **Notice:** Эта функция использует координаты мирового пространства.


### Аргументы

- *const  Math::[Vec3](../../../api/library/math/class.vec3_cpp.md) &* **p0** - Координаты начальной точки линии.
- *const  Math::[Vec3](../../../api/library/math/class.vec3_cpp.md) &* **p1** - Координаты конечной точки линии.
- *int* **mask** - Маска пересечений физики. Если передан **0**, функция вернёт **NULL**.
- *const [Vector](../../../api/library/containers/vector/class.vector_cpp.md)< [Ptr](../../../api/library/common/class.ptr_cpp.md)<[Node](../../../api/library/nodes/class.node_cpp.md)> > &* **exclude** - Массив исключаемых узлов.
- *const [Ptr](../../../api/library/common/class.ptr_cpp.md)<[PhysicsIntersection](../../../api/library/physics/class.physicsintersection_cpp.md)> &* **intersection** - Экземпляр класса [PhysicsIntersection](../../../api/library/physics/class.physicsintersection_cpp.md), содержащий данные о пересечении.

### Возвращаемое значение

Первый пересечённый объект, если найден; иначе 0.

**Пример использования**


Следующий пример показывает, как можно получить информацию о пересечении с помощью класса *PhysicsIntersection*. В этом примере линия — это невидимая трассируемая линия от точки камеры *(vec3 p0)* до точки указателя мыши *(vec3 p1)*. Последовательность выполнения следующая:


- Определить и инициализировать две точки (p0 и p1) с помощью функции *[Player::getDirectionFromScreen()](../../../api/library/players/class.player_cpp.md#getDirectionFromScreen_Vec3_Vec3_int_int_int_int_int_int_void)*.
- Создать экземпляр класса *PhysicsIntersection* для получения информации о пересечении.
- Проверить, есть ли пересечение с объектом. Функция *[getIntersection()](#getIntersection_Vec3_Vec3_int_PhysicsIntersection_Object)* возвращает пересечённый объект, когда объект пересекается с трассируемой линией.
- Когда объект пересекается с трассируемой линией, все поверхности пересечённого объекта изменяют параметры своего материала. Если у объекта есть форма, информация о ней будет выведена в консоль. Экземпляр класса PhysicsIntersection получает координаты точки пересечения и объект класса *Shape*. Все эти поля можно получить с помощью функций *[getShape()](../../../api/library/physics/class.physicsintersection_cpp.md#getShape_Shape), [getPoint()](../../../api/library/physics/class.physicsintersection_cpp.md#getPoint_Vec3)*.


```cpp
int AppWorldLogic::update()
{
	// инициализируем точки направления мыши
	Vec3 p0, p1;

	// получаем текущего игрока (камеру)
	PlayerPtr player = Game::getPlayer();
	if (player.get() == NULL)
		return 0;
	// получаем ширину и высоту главного окна приложения
	Math::ivec2 winsize = WindowManager::getMainWindow()->getClientSize();
	int width = winsize.x;
	int height = winsize.y;
	// получаем текущие координаты X и Y указателя мыши
	int mouse_x = Gui::getCurrent()->getMouseX();
	int mouse_y = Gui::getCurrent()->getMouseY();
	// получаем направление мыши от позиции игрока (p0) до курсора мыши (p1)
	player->getDirectionFromScreen(p0, p1, mouse_x, mouse_y, 0, 0, width, height);

	// создаём экземпляр объекта PhysicsIntersection для сохранения информации о пересечении
	PhysicsIntersectionPtr intersection = PhysicsIntersection::create();
	// получаем пересечение
	ObjectPtr object = Physics::getIntersection(p0, p1, 1, intersection);

	// если пересечение произошло, изменяем параметр материала объекта
	if (object)
	{
		for (int i = 0; i < object->getNumSurfaces(); i++)
		{
			object->setMaterialParameterFloat4("albedo_color", vec4(1.0f, 1.0f, 0.0f, 1.0f), i);
		}

		// если у пересечённого объекта есть форма, выводим информацию о пересечении
		ShapePtr shape = intersection->getShape();
		if (shape)
		{
			Log::message("physics intersection info: point: (%f %f %f) shape: %s\n", intersection->getPoint().x, intersection->getPoint().y, intersection->getPoint().z, shape->getTypeName());
		}
	}

	return 1;
}


```

## void setDeterminism ( bool determinism )

Задаёт значение, указывающее, обновляются ли объекты в определённом порядке. Детерминированный режим гарантирует, что все контакты решаются в предопределённом порядке, и визуализация физики в мире повторяема (на одном компьютере). Когда этот режим включён, движок выполняет дополнительную сортировку тел, форм и joints внутри islands после их построения. Детерминированный режим недоступен при пропущенных кадрах — это просто невозможно. Кроме того, могут быть различия в визуализации физики на разном оборудовании (например, AMD и Intel).
> **Notice:** Детерминизм гарантирован, если нет пропущенных кадров, используется одна и та же версия движка, а процессоры выполняют операции SSE одинаковым образом.
> Обратите внимание, что детерминированный режим не бесплатен — он может съедать 10-20% частоты кадров, и это также сильно зависит от сцены.


### Аргументы

- *bool* **determinism** - **true**, чтобы указать, что объекты обновляются в определённом порядке; **false**, чтобы указать, что порядок обновления объектов может изменяться. Значение по умолчанию: **false** (порядок обновления может изменяться).

## void setCurrentSubframeTime ( float time )

Принудительно выполняет симуляцию физики в течение указанного времени. Это означает, что до истечения заданного времени физика будет рассчитываться на каждом тике (кадре) физики, происходящем в соответствии с частотой кадров физики. Позволяет контролировать начальную точку симуляции физики.

```cpp
	Physics::setCurrentSubframeTime(Physics::getCurrentSubframeTime()+ifps));

/* ... */

```

## void setStableFPS ( bool stablefps )

Возвращает значение, указывающее, включена ли стабилизация времени кадра. Если текущая частота кадров движка значительно выше [fixed Physics framerate](../../../principles/physics/simulation.md#simulation_rate) (например, 120 FPS против 60 FPS), физика не будет обновляться на каждом кадре рендеринга (например, может обновляться каждый второй кадр). Результирующее время кадра станет нестабильным, короче-длиннее-короче-длиннее (*render -> render+physics -> render -> render+physics...*). Эта опция обеспечивает стабильное время кадра для более плавного пользовательского опыта, устраняя нежелательные "заикания" (однако средняя частота кадров снижается).
> **Notice:** По умолчанию эта опция включена. Но её можно отключить для увеличения средней частоты кадров, если приложение используется для машинного обучения или захвата последовательности кадров (video grabber), когда плавность не важна.

### Аргументы

- *bool* **stablefps** - **true**, чтобы включить стабилизацию времени кадра; **false** — чтобы отключить.

## bool isStableFPS ( ) const

Возвращает значение, указывающее, включена ли стабилизация времени кадра. Если текущая частота кадров движка значительно выше [fixed Physics framerate](../../../principles/physics/simulation.md#simulation_rate) (например, 120 FPS против 60 FPS), физика не будет обновляться на каждом кадре рендеринга (например, может обновляться каждый второй кадр). Результирующее время кадра станет нестабильным, короче-длиннее-короче-длиннее (*render -> render+physics -> render -> render+physics...*). Эта опция обеспечивает стабильное время кадра для более плавного пользовательского опыта, устраняя нежелательные "заикания" (однако средняя частота кадров снижается).
> **Notice:** По умолчанию эта опция включена. Но её можно отключить для увеличения средней частоты кадров, если приложение используется для машинного обучения или захвата последовательности кадров (video grabber), когда плавность не важна.

### Возвращаемое значение

**true**, если стабилизация времени кадра включена; иначе **false**.
## void setUpdateMode ( Physics::UPDATE_MODE mode )

[async](#UPDATE_MODE_ASYNC_RENDERING) режим самый быстрый и используется по умолчанию, однако он имеет задержку в один кадр (результаты расчётов применяются в следующем кадре) и некоторые нюансы, связанные с выполнением пользовательского кода в определённых случаях.

## void setMissedFrameLifetime ( float lifetime )

Задаёт время жизни для [missed frames](../../../principles/physics/simulation.md#missed_frames). Это значение определяет, как долго пропущенные кадры хранятся в буфере догона (catch-up buffer). Если текущая частота кадров движка ниже [fixed Physics framerate](../../../principles/physics/simulation.md#simulation_rate), некоторые кадры физики пропускаются, и симуляция начинает выглядеть как в эффекте замедленной съёмки (например, если целевая частота кадров физики — 60 FPS, а движок обновляется с частотой 30 FPS, симуляция будет выглядеть в 2 раза медленнее). Модуль физики попытается позже наверстать всё пропущенное, когда это возможно (например, когда частота кадров движка возрастает во время [waiting for GPU](../../../code/fundamentals/execution_sequence/index.md#waiting_gpu) для завершения рендеринга). Пропущенные кадры хранятся в буфере в течение некоторого времени (времени жизни), по истечении которого кадр удаляется из буфера и теряется навсегда.
### Аргументы

- *float* **lifetime** - Время жизни пропущенного кадра, в миллисекундах. Установка слишком высоких значений может привести к значительному потреблению памяти при слабом оборудовании (догон не выполняется при растущем количестве пропущенных кадров).
