### Перечисления

## SSL_HANDSHAKE

| Название | Описание |
|---|---|
| **SSL_HANDSHAKE_ERROR_NONE** = 0 | Операция ввода-вывода TLS/SSL завершена. |
| **SSL_HANDSHAKE_ERROR_SSL** = 1 | Произошла невосстановимая критическая ошибка в библиотеке SSL, обычно ошибка протокола. Очередь ошибок OpenSSL содержит дополнительную информацию об ошибке. Если возникла эта ошибка, дальнейшие операции ввода-вывода на соединении выполняться не должны. |
| **SSL_HANDSHAKE_ERROR_WANT_READ** = 2 | Код ошибки, возвращаемый, когда последней операцией была операция чтения из неблокирующего BIO. Это означает, что на данный момент было недостаточно данных для завершения операции. Если позже у базового BIO появятся данные для чтения, ту же функцию можно вызвать снова. |
| **SSL_HANDSHAKE_ERROR_WANT_WRITE** = 3 | Код ошибки, возвращаемый, когда последней операцией была запись в неблокирующий BIO, и не удалось отправить все данные в BIO. Когда BIO снова станет доступен для записи, ту же функцию можно вызвать снова. |
| **SSL_HANDSHAKE_ERROR_WANT_X509_LOOKUP** = 4 | Операция не завершилась, поскольку callback приложения запросил повторный вызов. Функцию ввода-вывода TLS/SSL следует вызвать снова позже. Детали зависят от приложения. |
| **SSL_HANDSHAKE_ERROR_SYSCALL** = 5 | Произошла некоторая невосстановимая критическая ошибка ввода-вывода. Очередь ошибок OpenSSL может содержать дополнительную информацию об ошибке. Для ввода-вывода сокета в системах Unix см. детали в errno. Если возникла эта ошибка, дальнейшие операции ввода-вывода на соединении выполняться не должны. |
| **SSL_HANDSHAKE_ERROR_ZERO_RETURN** = 6 | Партнёр по TLS/SSL закрыл соединение для записи, отправив оповещение close_notify. Больше данных прочитать нельзя. Обратите внимание, что *SSL_ERROR_ZERO_RETURN* не обязательно означает, что базовый транспорт был закрыт. |
| **SSL_HANDSHAKE_ERROR_WANT_CONNECT** = 7 | Операция не завершилась; ту же функцию ввода-вывода TLS/SSL следует вызвать снова позже. Базовый BIO ещё не был соединён с партнёром, и вызов блокировался бы в connect(). Функцию SSL следует вызвать снова, когда соединение будет установлено. |
| **SSL_HANDSHAKE_ERROR_WANT_ACCEPT** = 8 | Операция не завершилась; ту же функцию ввода-вывода TLS/SSL следует вызвать снова позже. Базовый BIO ещё не был соединён с партнёром, и вызов блокировался бы в accept(). Функцию SSL следует вызвать снова, когда соединение будет установлено. |
| **SSL_HANDSHAKE_ERROR_WANT_ASYNC** = 9 | Операция не завершилась, поскольку асинхронный движок всё ещё обрабатывает данные. Функцию ввода-вывода TLS/SSL следует вызвать снова позже. Функция должна вызываться из того же потока, из которого был сделан исходный вызов. |
| **SSL_HANDSHAKE_ERROR_WANT_ASYNC_JOB** = 10 | Асинхронное задание не удалось запустить, поскольку в пуле не было доступных асинхронных заданий. Приложению следует повторить операцию после завершения текущей выполняемой асинхронной операции для текущего потока. |
| **SSL_HANDSHAKE_ERROR_WANT_CLIENT_HELLO_CB** = 11 | Операция не завершилась, поскольку callback приложения, заданный через *SSL_CTX_set_client_hello_cb()*, запросил повторный вызов. Функцию ввода-вывода TLS/SSL следует вызвать снова позже. Детали зависят от приложения. |
| **SSL_HANDSHAKE_OK** = 100 | Операция handshake прошла успешно. |
| **SSL_HANDSHAKE_FAILED** = 101 | Операция handshake завершилась неудачно. |

## SSL_CTX_METHOD

| Название | Описание |
|---|---|
| **SSL_CTX_METHOD_TLS** = 0 | Универсальные гибкие по версии методы SSL/TLS. Фактическая используемая версия протокола будет согласована как наивысшая версия, взаимно поддерживаемая клиентом и сервером. В настоящее время поддерживаются протоколы TLS 1.0, TLS 1.1 и TLS 1.2. |
| **SSL_CTX_METHOD_TLS_1_0** = 1 | Протокол *Transport Layer Security Version 1.0*. |
| **SSL_CTX_METHOD_TLS_1_1** = 2 | Протокол *Transport Layer Security Version 1.1*. |
| **SSL_CTX_METHOD_TLS_1_2** = 3 | Протокол *Transport Layer Security Version 1.2*. |
| **SSL_CTX_METHOD_DTLS** = 4 | Гибкие по версии методы DTLS. В настоящее время поддерживаются протоколы DTLS 1.0 и DTLS 1.2. |
| **SSL_CTX_METHOD_DTLS_1** = 5 | Протокол *Datagram Transport Layer Security Version 1.0*. |
| **SSL_CTX_METHOD_DTLS_1_2** = 6 | Протокол *Datagram Transport Layer Security Version 1.2*. |

### Методы класса

---

## SSLSocket ( )

Конструктор. Создаёт новый SSL-сокет с параметрами по умолчанию (TLS).
## SSLSocket ( Socket::SOCKET_TYPE socket_type , SSLSocket::SSL_CTX_METHOD ssl_method )

Конструктор. Создаёт новый SSL-сокет с указанными параметрами.
### Аргументы

- *[Socket::SOCKET_TYPE](../../../api/library/networking/class.socket_cpp.md#SOCKET_TYPE)* **socket_type** - Тип SSL-сокета.
- *[SSLSocket::SSL_CTX_METHOD](../../../api/library/networking/class.sslsocket_cpp.md#SSL_CTX_METHOD)* **ssl_method** - Используемый метод SSL-соединения.

## void close ( )

Закрывает сокет.
## bool accept ( const Ptr < Socket > & socket )

Принимает соединение на сокете.
### Аргументы

- *const [Ptr](../../../api/library/common/class.ptr_cpp.md)<[Socket](../../../api/library/networking/class.socket_cpp.md)> &* **socket** - Сокет, привязанный к адресу и прослушивающий соединения.

### Возвращаемое значение

true, если соединение принято; иначе false.
## bool connect ( )

Инициирует соединение на сокете.
### Возвращаемое значение

true, если соединение инициализировано; иначе false.
## bool load ( SSLSocket::LOADER_TYPE loader_type , const char * path )

Загружает сертификат из файла.
### Аргументы

- *[SSLSocket::LOADER_TYPE](../../../api/library/networking/class.sslsocket_cpp.md#LOADER_TYPE)* **loader_type** - Тип сертификата, одно из значений [LOADER_TYPE](#LOADER_TYPE_RSA_KEY).
- *const char ** **path** - Путь к файлу сертификата.

### Возвращаемое значение

true, если сертификат успешно загружен; иначе false.
## bool parse ( SSLSocket::LOADER_TYPE loader_type , const char * data )

Разбирает указанный сертификат.
### Аргументы

- *[SSLSocket::LOADER_TYPE](../../../api/library/networking/class.sslsocket_cpp.md#LOADER_TYPE)* **loader_type** - Тип сертификата, одно из значений [LOADER_TYPE](#LOADER_TYPE_RSA_KEY).
- *const char ** **data** - Данные сертификата.

### Возвращаемое значение

true, если сертификат успешно разобран; иначе false.
## SSLSocket::SSL_HANDSHAKE handshake ( )

Запускает handshake и возвращает результат.
### Возвращаемое значение

Статус handshake.
## bool isAvailable ( ) const

Проверяет, установлен ли сокет, но не открыт.
### Возвращаемое значение

true, если сокет доступен; иначе false.
## bool isCertificateVerified ( ) const

Возвращает значение, указывающее, успешно ли проверен SSL-сертификат сокета.
### Возвращаемое значение

true, если SSL-сертификат сокета успешно проверен; иначе false.
## int pending ( ) const

Возвращает количество байт, доступных для немедленного получения без чтения из объекта сокета. Эта функция необходима при работе с циклами событий.
### Возвращаемое значение

Количество байт.
## size_t read ( void * ptr , size_t size , size_t nmemb ) const

Читает указанное количество блоков указанного размера из SSL-соединения в указанный буфер назначения.
### Аргументы

- *void ** **ptr** - Указатель на буфер назначения, в который будут прочитаны данные.
- *size_t* **size** - Размер блока сообщения в байтах.
- *size_t* **nmemb** - Количество блоков сообщения для чтения из SSL-соединения.

### Возвращаемое значение

Количество фактически прочитанных байт.
## size_t write ( const void * ptr , size_t size , size_t nmemb ) const

Записывает указанное количество блоков указанного размера из указанного буфера источника в SSL-соединение.
### Аргументы

- *const void ** **ptr** - Указатель на буфер источника, из которого будут записаны данные.
- *size_t* **size** - Размер блока сообщения в байтах.
- *size_t* **nmemb** - Количество блоков сообщения для записи в SSL-соединение.

### Возвращаемое значение

Количество фактически записанных байт.
## size_t peek ( void * ptr , size_t size , size_t nmemb ) const

Читает указанное количество блоков указанного размера из SSL-соединения в указанный буфер назначения. Этот метод идентичен *[read](../../...md#read_void_size_t_size_t_size_t)*, за исключением того, что во время чтения из базового BIO фактически не удаляются байты, поэтому последующий вызов *[read](../../...md#read_void_size_t_size_t_size_t)* вернёт как минимум те же байты.
### Аргументы

- *void ** **ptr** - Указатель на буфер назначения, в который будут прочитаны данные.
- *size_t* **size** - Размер блока сообщения в байтах.
- *size_t* **nmemb** - Количество блоков сообщения для записи в SSL-соединение.

### Возвращаемое значение

Количество фактически записанных байт.
