# Unigine::AsyncQueue Class (CPP)

**Header:** #include <UnigineAsyncQueue.h>

> **Notice:** This class is a singleton.


Загрузка файлов/мешей/изображений/узлов по требованию выполняется в отдельном системном потоке, в дополнение к асинхронной потоковой передаче контента. Этот класс используется для управления асинхронной загрузкой данных. Можно управлять очередью загрузки, организуя файлы в группы и задавая индивидуальные веса внутри этих групп.


Чтобы загрузить файлы по требованию, вызывайте функции в следующем порядке:


1. Сначала вызывается функция *[loadFile()](../../...md#loadFile_cstr_int_float_int)*, чтобы поместить файл в очередь загрузки и получить ***ID***, который будет использоваться для идентификации ресурса в последующих операциях.
2. После этого можно выполнять различные операции:

  - *[forceFile()](../../...md#forceFile_int_int)* — для немедленной загрузки файла.
  - *[removeFile()](../../...md#removeFile_int_int)* — для удаления файла из очереди, если его больше не нужно загружать, или для удаления файла из списка загруженных файлов, если он был загружен, но больше не нужен.
  - *[checkFile()](../../...md#checkFile_int_int)* — для проверки, был ли запрошен указанный файл для загрузки через *loadFile()* или он уже загружен.


Тот же алгоритм справедлив для:


- **Мешей** — см. методы *[loadMesh()](../../...md#loadMesh_cstr_int_float_int)*, *[forceMesh()](../../...md#forceMesh_int_int)*, *[getMesh()](../../...md#getMesh_int_Mesh)*, *[takeMesh()](../../...md#takeMesh_int_Mesh)*, *[checkMesh()](../../...md#checkMesh_int_int)* и *[removeMesh()](../../...md#removeMesh_int_int)*.
- **Изображений** — см. методы *[loadImage()](../../...md#loadImage_cstr_int_float_int)*, *[forceImage()](../../...md#forceImage_int_int)*, *[getImage()](../../...md#getImage_int_Image)*, *[takeImage()](../../...md#takeImage_int_Image)*, *[checkImage()](../../...md#checkImage_int_int)* и *[removeImage()](../../...md#removeImage_int_int)*.
- **Узлов** — см. методы *[loadNode()](../../...md#loadNode_cstr_int_float_int)*, *[forceNode()](../../...md#forceNode_int_int)*, *[getNode()](../../...md#getNode_int_Node)*, *[takeNode()](../../...md#takeNode_int_Node)*, *[checkNode()](../../...md#checkNode_int_int)* и *[removeNode()](../../...md#removeNode_int_int)*.


Чтобы получить загруженный ресурс (изображение, меш или узел), можно использовать следующие 2 группы методов:


- **Get-методы** — эти методы возвращают загруженный ресурс:

  - *[getImage()](../../...md#getImage_int_Image)*
  - *[getMesh()](../../...md#getMesh_int_Mesh)*
  - *[getNode()](../../...md#getNode_int_Node)*
- **Take-методы** — эти методы возвращают загруженный ресурс и удаляют его из списка загруженных:

  - *[takeImage()](../../...md#takeImage_int_Image)*
  - *[takeMesh()](../../...md#takeMesh_int_Mesh)*
  - *[takeNode()](../../...md#takeNode_int_Node)*


Например:


```cpp
// задаём относительные пути к ресурсам для загрузки в очередь
static const char *meshes[] = {
	"meshes/box.mesh",
	"meshes/capsule.mesh",
	"meshes/cbox.mesh",
};

#define ARRAY_LENGTH(array) static_cast<int>(sizeof(array) / sizeof(array[0]))

struct AsyncLoadRequest
{
	String name;
	int id;
};

Vector<AsyncLoadRequest> mesh_load_requests;

void AsyncSample::init()
{

	// добавляем меши в очередь загрузки
	for (int i = 0; i < ARRAY_LENGTH(meshes); ++i)
	{
		const char *name = meshes[i];
		AsyncLoadRequest request;
		request.name = name;
		request.id = AsyncQueue::loadMesh(name);
		mesh_load_requests.append(request);
	}

}

void AsyncSample::update()
{
	// проверяем запросы на загрузку мешей
	for (int i = 0; i < mesh_load_requests.size(); ++i)
	{
		const auto &r = mesh_load_requests[i];

		if (!AsyncQueue::checkMesh(r.id))
			continue;

		// удаляем меш из списка загруженных мешей и выводим сообщение
		AsyncQueue::removeMesh(r.id);
		Log::message("Loaded mesh \"%s\"\n", r.name.get());

		mesh_load_requests.remove(i--);
	}
}


```


### Обработка событий


Вы можете добавлять обработчики события "ресурс загружен" для файлов, изображений, мешей или узлов и выполнять определённые действия при загрузке ресурса. Пример ниже показывает, как добавить обработчик события "загружено" для ресурса изображения, который сообщает имя и id загруженного изображения.

> **Notice:** Не вызывайте [***take-методы***](#take_methods) внутри функции-обработчика, если вы не абсолютно уверены, что ресурс принадлежит вам, иначе внутренние менеджеры движка будут вынуждены загружать его снова и снова каждый раз. В таких случаях рекомендуется использовать [***get-методы***](#take_methods).


```cpp
// задаём относительные пути к ресурсам для загрузки в очередь
static const char *textures[] = {
	"textures/black_d.texture",
	"textures/blue_d.texture",
	"textures/green_d.texture",
	"textures/orange_d.texture",
	"textures/red_d.texture",
	"textures/white_d.texture",
	"textures/yellow_d.texture",
};

#define ARRAY_LENGTH(array) static_cast<int>(sizeof(array) / sizeof(array[0]))

void AsyncSample::init()
{

	// добавляем текстуры в очередь загрузки
	for (int i = 0; i < ARRAY_LENGTH(textures); ++i)
		AsyncQueue::loadImage(textures[i]);
	// подписываемся на событие ImageLoaded
	AsyncQueue::getEventImageLoaded().connect(this, &AsyncSample::image_loaded);

}

// функция-обработчик события загрузки изображения
void AsyncSample::image_loaded(const char *name, int id)
{
	AsyncQueue::removeImage(id);
	Log::message("Image \"%s\" loaded, ID: %d\n", name, id);
}


```


### Асинхронное и многопоточное выполнение


Помимо управления фоновой загрузкой файлов и потоковой передачей по требованию, класс ***AsyncQueue*** предоставляет функциональность асинхронного и многопоточного выполнения общего назначения. Он позволяет планировать выполнение пользовательских задач в выделенных потоках, включая параллельное выполнение на нескольких ядрах CPU.


Этот класс поддерживает как асинхронные, так и синхронные многопоточные рабочие процессы с опциональной синхронизацией по кадрам. Он позволяет переносить дорогостоящие операции, такие как процедурная генерация или сложная обработка данных, без блокировки главного потока.


Для тонкого контроля над размещением задач ***AsyncQueue*** предоставляет несколько выделенных типов потоков через перечисление ***[ASYNC_THREAD](#ASYNC_THREAD)***:


- **MAIN** - главный поток движка.
- **SYNC** - поток Sync-пула для задач, синхронизированных по кадрам.
- **ASYNC** - асинхронный поток движка общего назначения.
- **COMMON** - поток Common-пула с гибкой балансировкой нагрузки между пулами.
- **CRITICAL** - критический поток для задач с высоким приоритетом.
- **BACKGROUND** - фоновый поток для длительных задач.
- **FILE_STREAM** - поток для операций дискового ввода-вывода.
- **GPU_STREAM** - поток для работы с ресурсами GPU.
- **NEW** - изолированный поток, взятый из пула потоков.


***AsyncQueue*** также предоставляет управление приоритетом планирования задач через перечисление ***[ASYNC_PRIORITY](#ASYNC_PRIORITY)*** (8 уровней от *CRITICAL* до *IDLE*). Приоритет по умолчанию для *runAsync()* — *BACKGROUND*.


![](thread_sequence.png)

*Microprofiletool: конвейер задач с использованием всех типов потоков.*


Комбинируя эти типы потоков и приоритеты, вы можете проектировать гибкие цепочки выполнения, эффективно распределяющие нагрузку между подсистемами движка.


Многопоточные методы создают экземпляры *[CPUShader](../../../api/library/common/mt/class.cpushader_cpp.md)*, а однопоточные методы создают экземпляры *[CPUTask](../../../api/library/common/mt/class.cputask_cpp.md)*. Эти классы доступны напрямую только в C++, в то время как *AsyncQueue* предоставляет унифицированный интерфейс для C++, C# и UnigineScript. Подробнее о пулах потоков, приоритете задач и синхронизации по кадрам см. в статье **[UNIGINE Thread System](../../../code/fundamentals/thread_system/index.md)**.

## AsyncQueue Class

### Перечисления

## ASYNC_THREAD

| Name | Description |
|---|---|
| **ASYNC_THREAD_MAIN** = 0 | Главный поток движка. Требуется для любой операции, взаимодействующей с объектами сцены или состоянием движка напрямую. Используйте этот поток при выполнении обратных вызовов, которые должны безопасно изменять элементы сцены или обращаться к ним. Обычно используется для передачи результатов финальной стадии фоновых задач. |
| **ASYNC_THREAD_SYNC** = 1 | Поток Sync-пула. Задачи в этом пуле синхронизированы по кадрам, а главный поток выступает в роли воркера во время синхронных операций. |
| **ASYNC_THREAD_ASYNC** = 2 | Асинхронный поток общего назначения, используемый движком для таких задач, как предварительная загрузка, обновление ландшафта, потоковая передача данных и другие фоновые операции. Чрезмерное использование этого потока может задержать основные системы движка. |
| **ASYNC_THREAD_COMMON** = 3 | Поток Common-пула. Воркеры в этом пуле могут забирать задачи из нескольких других пулов (Sync, Async, Common), обеспечивая гибкую балансировку нагрузки в системе потоков. |
| **ASYNC_THREAD_CRITICAL** = 4 | Критический поток для задач с высоким приоритетом, которые должны быть обработаны как можно скорее. |
| **ASYNC_THREAD_BACKGROUND** = 5 | Фоновый поток с наименьшим приоритетом. Редко используется самим движком, в основном предназначен для пользовательских процедурных операций, таких как изменение геометрии. Безопасен для длительных фоновых задач, так как не мешает потоковой передаче или другим критическим системам движка. |
| **ASYNC_THREAD_FILE_STREAM** = 6 | Выделенный поток для операций ввода-вывода файлов. Похож по приоритету на ASYNC, но выделен отдельно, чтобы снизить конкуренцию между работой CPU и доступом к диску. Подходит для загрузки/сохранения геометрии, потоковой передачи данных с диска или обработки интенсивного ввода-вывода без влияния на основные асинхронные системы. Перегрузка этого потока может повлиять на производительность потоковой передачи. |
| **ASYNC_THREAD_GPU_STREAM** = 7 | Специализированный поток с выделенной очередью команд для передачи данных из RAM в VRAM. Используется для асинхронного создания ресурсов GPU (например, *[Texture](../../../api/library/rendering/class.texture_cpp.md)*, *[MeshRender](../../../api/library/rendering/class.meshrender_cpp.md)*) из соответствующих объектов RAM (*[Image](../../../api/library/common/class.image_cpp.md)*, *[Mesh](../../../api/library/rendering/class.mesh_cpp.md)*). Идеально подходит для реализации собственной системы потоковой передачи данных или динамического обновления данных GPU. |
| **ASYNC_THREAD_NEW** = 8 | Создаёт новый изолированный поток из внутреннего пула потоков. Предназначен для пользовательских операций, которые не должны блокировать существующие потоки движка или мешать им. Идеально подходит для длительных или экспериментальных задач. Этот поток работает независимо и не влияет на системы движка. |
| **NUM_ASYNC_THREADS** = 9 | Количество предопределённых типов асинхронных потоков. Используется для проверки или перебора констант типов потоков. |

## ASYNC_PRIORITY

| Name | Description |
|---|---|
| **ASYNC_PRIORITY_CRITICAL** = 0 | Наивысший приоритет. Задачи с этим уровнем планируются к выполнению раньше всех остальных. |
| **ASYNC_PRIORITY_HIGHEST** = 1 | Второй по величине уровень приоритета. |
| **ASYNC_PRIORITY_ABOVENORMAL** = 2 | Уровень приоритета выше обычного. |
| **ASYNC_PRIORITY_NORMAL** = 3 | Уровень приоритета по умолчанию для задач общего назначения. |
| **ASYNC_PRIORITY_BELOWNORMAL** = 4 | Уровень приоритета ниже обычного. |
| **ASYNC_PRIORITY_LOWEST** = 5 | Второй по величине из низких уровней приоритета. |
| **ASYNC_PRIORITY_BACKGROUND** = 6 | Фоновый уровень приоритета для несрочных задач. |
| **ASYNC_PRIORITY_IDLE** = 7 | Наименьший приоритет. Задачи планируются только тогда, когда нет задач с более высоким приоритетом. |

## static Event<const char *, int> getEventNodeLoaded () const

Событие, срабатывающее при загрузке узла. Вы можете подписываться на события через *connect()* и отписываться через *disconnect()*. Также для удобства можно использовать классы *[EventConnection](../../../api/library/common/events/class.eventconnection_cpp.md)* и *[EventConnections](../../../api/library/common/events/class.eventconnections_cpp.md)* (см. примеры ниже).

> **Notice:** Подробнее см. статью [Event Handling](../../../code/fundamentals/events/index_cpp.md).

 Сигнатура обработчика события выглядит следующим образом: *myhandler(const char * **name**, int **id**)*

**Пример использования**

```cpp
// реализация обработчика события NodeLoaded
void nodeloaded_event_handler(const char * name,  int id)
{
	Log::message("\Обработка события NodeLoaded\n");
}

//////////////////////////////////////////////////////////////////////////////
//  1. Несколько подписок можно связать с экземпляром класса EventConnections,
//  который затем можно использовать для отмены всех этих подписок сразу
//////////////////////////////////////////////////////////////////////////////

// создаём экземпляр класса EventConnections
EventConnections nodeloaded_event_connections;

// связываем с этим экземпляром при подписке на событие (можно связывать подписки на разные события)
AsyncQueue::getEventNodeLoaded().connect(nodeloaded_event_connections, nodeloaded_event_handler);

// другие подписки также связаны с этим экземпляром EventConnections
// (например, можно подписываться с помощью лямбда-функций)
AsyncQueue::getEventNodeLoaded().connect(nodeloaded_event_connections, [](const char * name,  int id) {
		Log::message("\Обработка события NodeLoaded (лямбда).\n");
	}
);

// ...

// позже все эти связанные подписки можно удалить одной строкой
nodeloaded_event_connections.disconnectAll();

//////////////////////////////////////////////////////////////////////////////
//  2. Можно подписываться и отписываться через экземпляр класса EventConnection.
//  А также включать и отключать это конкретное соединение при необходимости.
//////////////////////////////////////////////////////////////////////////////

// создаём экземпляр класса EventConnection
EventConnection nodeloaded_event_connection;

// подписываемся на событие NodeLoaded с функцией-обработчиком, сохраняя соединение
AsyncQueue::getEventNodeLoaded().connect(nodeloaded_event_connection, nodeloaded_event_handler);

// ...

// можно временно отключить конкретное соединение события для выполнения определённых действий
nodeloaded_event_connection.setEnabled(false);

// ... выполняемые действия

// и снова включить его при необходимости
nodeloaded_event_connection.setEnabled(true);

// ...

// удаляем подписку на событие NodeLoaded через соединение
nodeloaded_event_connection.disconnect();

//////////////////////////////////////////////////////////////////////////////
//  3. Можно добавить экземпляр EventConnection/EventConnections как член класса,
//  обрабатывающего событие. В этом случае все связанные подписки будут
```
