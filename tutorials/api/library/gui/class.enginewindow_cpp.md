# Unigine::EngineWindow Class (CPP)

**Header:** #include <UnigineWindowManager.h>


Этот базовый класс работает с окнами движка: их компонентами, связями с другими окнами, размером, позицией, визуальным представлением и другими характеристиками.


При создании [window viewport](../../../api/library/gui/class.enginewindowviewport_cpp.md) или [window group](../../../api/library/gui/class.enginewindowgroup_cpp.md) создаётся окно движка.


Изображение ниже демонстрирует компоненты окна, которыми можно управлять методами класса EngineWindow.


![Window components](window_structure.png)


Чтобы создать окно движка, используйте один из конструкторов класса *[EngineWindowViewport](../../../api/library/gui/class.enginewindowviewport_cpp.md)* или *[EngineWindowGroup](../../../api/library/gui/class.enginewindowgroup_cpp.md)*. Например:


```cpp
// создаём окно движка указанного размера с указанным именем
EngineWindowViewportPtr window = EngineWindowViewport::create("New window", 580, 300);

```


Затем, используя методы класса *EngineWindow*, можно задать внешний вид окна (например, установить заголовок, иконку, изменить прозрачность, добавить границы и т.д.), а также свойства (может ли окно быть вложенным или стать группой), определить его стиль (системный или движковый), изменить состояние окна (показано/скрыто, свёрнуто/развёрнуто, в фокусе и т.д.), управлять пересечениями окон и событиями.


### Настройка позиции и размера


В UNIGINE размер и координаты позиции окна измеряются как в [logical units](../../../principles/dpi/index.md), так и в пикселях:


- Размер и позиция в *единицах* не зависят от [DPI scale](#getDpiScale_float) и всегда остаются неизменными. Можно изменить размер окна и клиентской области через **[setSize](../../...md#setSize_ivec2_void)** и **[setClientSize](../../...md#setClientSize_ivec2_void)**, задать [minimum](#setMinSize_ivec2_void) и [maximum size](#setMaxSize_ivec2_void) и установить позицию окна и клиента через соответствующие методы. Все они работают с единицами.
- Размер и позиция в *пикселях* вычисляются путём умножения размера в единицах на текущий [DPI scale](#getDpiScale_float). Его можно получить с помощью одного из методов/свойств, связанных с *RenderSize* (например, **[getRenderSize](../../...md#getRenderSize_ivec2)** и т.д.). Когда DPI-масштаб равен 100%, *1 единица соответствует 1 пикселю*. > **Notice:** DPI-масштабирование применяется только при включённом флаге `auto_dpi`. Текущее значение флага можно проверить через консоль или с помощью **[WindowManager::isAutoDpiScaling](../../../api/library/gui/class.windowmanager_cpp.md#isAutoDpiScaling_int)**. > Чтобы определить, как ОС обрабатывает DPI-масштаб, укажите *[DPI awareness mode](../../../api/library/gui/class.windowmanager_cpp.md#DPI_AWARENESS)*.


Эту информацию следует учитывать при изменении размера текстур, вычислении пересечений с мышью и т.д. Размер и позицию окна следует задавать индивидуально, в зависимости от ситуации.


> **Notice:** При необходимости можно преобразовать координаты размера и позиции *из единиц в пиксели* и наоборот:
> - Используйте один из методов **[toRenderSize](../../...md#toRenderSize_int_int)** или **[toUnitSize](../../...md#toUnitSize_int_int)** для преобразования размера.
> - Используйте **[globalToLocalUnitPosition](../../...md#globalToLocalUnitPosition_ivec2_ivec2)** для преобразования координат в пикселях в единицы или **[localUnitToGlobalPosition](../../...md#localUnitToGlobalPosition_ivec2_ivec2)** для обратного преобразования.


В следующем примере позиции окна и клиентской области (в единицах) изменяются на позицию курсора мыши при нажатии клавиш **P** или **C** соответственно:


<details>
<summary>AppSystemLogic.cpp</summary>

```cpp
#include <UnigineEngine.h>
#include <UnigineLogic.h>
#include <UnigineWindowManager.h>

using namespace Unigine;
using namespace Math;

EngineWindowViewportPtr system_viewport;

int AppSystemLogic::init()
{

	// создаём отдельный window viewport
	system_viewport = EngineWindowViewport::create("Separate System Viewport", 400, 350);
	// задаём начальную позицию
	system_viewport->setPosition(ivec2(30, 30));

	// отрисовываем window viewport
	system_viewport->show();

	return 1;
}

int AppSystemLogic::update()
{

	// изменяем позицию окна на позицию курсора мыши при нажатии 'P'
	if (Input::isKeyDown(Input::KEY_P))
	{

		if (system_viewport.isDeleted() == false)
			system_viewport->setPosition(mouse_pos);
	}

	// изменяем позицию клиентской области на позицию курсора мыши при нажатии 'C'
	if (Input::isKeyDown(Input::KEY_C))
	{
		if (system_viewport.isDeleted() == false)
			system_viewport->setClientPosition(mouse_pos);
	}

	return 1;
}
```

### Настройка визуального представления


Визуальное представление окна включает все доступные параметры окна, такие как заголовок и панель заголовка, иконка, границы, прозрачность и стиль окна (движковый или системный).


Ниже приведены некоторые примеры окон:


<details>
<summary>AppSystemLogic.cpp</summary>

```cpp
#include <UnigineEngine.h>
#include <UnigineLogic.h>
#include <UnigineWindowManager.h>

using namespace Unigine;
using namespace Math;

EngineWindowViewportPtr system_viewport;

EngineWindowViewportPtr system_viewport_borderless;
EngineWindowViewportPtr engine_viewport_borderless;
EngineWindowViewportPtr engine_viewport;

{
	// создаём отдельный системный viewport
	system_viewport = EngineWindowViewport::create("Window", 200, 200);
	// задаём начальную позицию
	system_viewport->setPosition(ivec2(30, 30));

	// изменяем размер
	system_viewport->setSize(ivec2(400, 350));

	// отрисовываем window viewport
	system_viewport->show();

	// создаём отдельный системный viewport с отключёнными границами и панелью заголовка
	system_viewport_borderless = EngineWindowViewport::create(400, 350);
	system_viewport_borderless->setPosition(ivec2(460, 30));
	system_viewport_borderless->setSize(ivec2(400, 350));
	// отключаем границы
	system_viewport_borderless->setBordersEnabled(false);
	// отключаем панель заголовка
	system_viewport_borderless->setTitleBarEnabled(false);
	system_viewport_borderless->show();

	// создаём отдельный engine viewport без границ
	engine_viewport_borderless = EngineWindowViewport::create("Window", 400, 350);
	engine_viewport_borderless->setPosition(ivec2(460, 30));
	engine_viewport_borderless->setEngineStyle(true);
	engine_viewport_borderless->setSize(ivec2(400, 350));
	// отключаем границы
	engine_viewport_borderless->setBordersEnabled(false);
	engine_viewport_borderless->show();

	// создаём отдельный engine viewport с границами
	engine_viewport = EngineWindowViewport::create("Window", 400, 350);
	engine_viewport->setPosition(ivec2(460, 30));
	engine_viewport->setEngineStyle(true);
	engine_viewport->setSize(ivec2(400, 350));
	engine_viewport->show();

	return 1;
}
```

### Настройка порядка


В следующем примере порядок окна под курсором изменяется при нажатии определённой клавиши: **T** — чтобы окно оказалось поверх всех остальных окон, **A** — чтобы окно всегда отрисовывалось поверх остальных окон.

```cpp
	// изменяем размер
	system_viewport->setSize(ivec2(400, 350));

	// отрисовываем window viewport
	system_viewport->show();

	// создаём отдельный системный viewport с отключёнными границами и панелью заголовка
	system_viewport_borderless = EngineWindowViewport::create(400, 350);
	system_viewport_borderless->setPosition(ivec2(460, 30));

	// создаём отдельный engine viewport без границ

	engine_viewport_borderless->setPosition(ivec2(460, 30));
	engine_viewport_borderless->setEngineStyle(true);
	engine_viewport_borderless->setSize(ivec2(400, 350));
	// отключаем границы
	engine_viewport_borderless->setBordersEnabled(false);
	engine_viewport_borderless->show();

	// создаём отдельный engine viewport с границами
	engine_viewport = EngineWindowViewport::create("Window", 400, 350);
	engine_viewport->setPosition(ivec2(460, 30));
	engine_viewport->setEngineStyle(true);
	engine_viewport->setSize(ivec2(400, 350));
	engine_viewport->show();

	return 1;
}

int AppSystemLogic::update()
{
	// получаем текущую позицию мыши
	ivec2 mouse_pos = Input::getMousePosition();

	// делаем так, чтобы окно под курсором оказалось поверх остальных при нажатии 'T'
	if (Input::isKeyDown(Input::KEY_T))
	{
		current_window = WindowManager::getUnderCursorWindow();
		if (current_window.isDeleted() == false)
			current_window->toTop();
	}

	// делаем так, чтобы окно под курсором всегда было поверх остальных при нажатии 'A'
	if (Input::isKeyDown(Input::KEY_A))
	{
		current_window = WindowManager::getUnderCursorWindow();
		if (current_window.isDeleted() == false)
			current_window->setAlwaysOnTop(true);
	}

	return 1;
}
```

### Работа с модальными окнами


Следующий пример демонстрирует, как создавать модальные окна и добавлять модальные дочерние окна к главному окну. Кроме того, главное окно содержит сообщение, информирующее пользователя, может ли он закрыть окно.


<details>
<summary>AppSystemLogic.cpp</summary>

```cpp
#include "AppSystemLogic.h"
#include <UnigineEngine.h>
#include <UnigineLogic.h>
#include <UnigineWindowManager.h>

using namespace Unigine;
using namespace Math;

WidgetLabelPtr label;
EngineWindowViewportPtr main_window;

int AppSystemLogic::init()
{
	// главное окно
	main_window = WindowManager::getMainWindow();
	main_window->setSize(ivec2(1600, 900));
	main_window->setPosition(ivec2(30, 30));
	main_window->setCanBeNested(false);
	main_window->setCanCreateGroup(false);

	// добавляем информационную метку к главному окну
	label = WidgetLabel::create("");
	label->setFontOutline(1);
	label->setLifetime(Widget::LIFETIME_WINDOW);
	label->setFontColor(vec4_red);
	main_window->addChild(label, Gui::ALIGN_LEFT);

	// первое модальное окно главного окна
	EngineWindowViewportPtr main_modal_0 = EngineWindowViewport::create("Modal for Main 0", 600, 650);
	main_modal_0->setPosition(ivec2(50, 250));
	main_modal_0->setCanBeNested(false);
	main_modal_0->setCanCreateGroup(false);
	main_modal_0->show();
	main_modal_0->setModal(main_window);

	// второе модальное окно главного окна
	EngineWindowViewportPtr main_modal_1 = EngineWindowViewport::create("Modal for Main 1", 900, 650);
	main_modal_1->setPosition(ivec2(700, 250));
	main_modal_1->setCanBeNested(false);
	main_modal_1->setCanCreateGroup(false);
	main_modal_1->show();
	main_modal_1->setModal(main_window);

	return 1;
}

int AppSystemLogic::update()
{
	String text;

	// проверяем, всё ещё открыты ли модальные дочерние окна главного окна
	if (main_window->isModalParent())
		text += "You CANNOT close this window. Please close modal children first.\n";
	else
		text += "You CAN close this window.\n";

	// отрисовываем информационную метку
	label->setText(text);

	return 1;
}


```

</details>

### Методы класса

## Ptr < Gui > getGui () const

Возвращает текущий родительский Gui для окна. Если окно вложенное, этот Gui отличается от [SelfGui](#getSelfGui_Gui).
### Возвращаемое значение

Текущий экземпляр Gui.
## int getDisplayIndex () const

Возвращает текущий номер дисплея, на котором в данный момент отображается окно. Для отдельных окон этот индекс запрашивается у системного прокси; для вложенных окон индекс предоставляется на основе расположения центральной точки клиента.
### Возвращаемое значение

Текущий номер дисплея, на котором в данный момент отображается окно.
## bool isNested () const

Возвращает текущее значение, указывающее, является ли это вложенным окном или группой окон.
### Возвращаемое значение

**true**, если это вложенное окно или группа окон; иначе **false**.
## bool isSeparate () const

Возвращает текущее значение, указывающее, является ли это отдельным окном или группой окон.
### Возвращаемое значение

**true**, если это отдельное окно или группа окон; иначе **false**.
## Ptr < Gui > getSelfGui () const

Возвращает текущий экземпляр Gui для окна. Этот Gui остаётся неизменным на протяжении всего жизненного цикла окна.
### Возвращаемое значение

Текущий экземпляр Gui.
## void setPosition ( const Math:: ivec2 & position )

Устанавливает новую позицию [top left corner](#window_structure) окна в экранных координатах (пикселях). В случае нескольких дисплеев позиция задаётся относительно главного дисплея.
> **Notice:** Этот метод следует применять к отдельному или родительскому окну, использование этого метода для вложенного окна недопустимо.


### Аргументы

- *const  Math::[ivec2](../../../api/library/math/class.ivec2_cpp.md)&* **position** - Экранная позиция окна (координаты верхнего левого угла).

## Math:: ivec2 getPosition () const

Возвращает текущую позицию [top left corner](#window_structure) окна в экранных координатах (пикселях). В случае нескольких дисплеев позиция задаётся относительно главного дисплея.

Событие, срабатывающее при удалении окна из стека. Вы можете подписываться на события через *connect()* и отписываться через *disconnect()*. Также для удобства можно использовать классы *[EventConnection](../../../api/library/common/events/class.eventconnection_cpp.md)* и *[EventConnections](../../../api/library/common/events/class.eventconnections_cpp.md)* (см. примеры ниже).

> **Notice:** Подробнее см. статью [Event Handling](../../../code/fundamentals/events/index_cpp.md).

 Сигнатура обработчика события выглядит следующим образом: *myhandler()*
<details>

**Пример использования**

```cpp
// реализация обработчика события Unstack
void unstack_event_handler()
{
	Log::message("\Обработка события Unstack\n");
}

//////////////////////////////////////////////////////////////////////////////
//  1. Несколько подписок можно связать с экземпляром класса EventConnections,
//  который затем можно использовать для отмены всех этих подписок сразу
//////////////////////////////////////////////////////////////////////////////

// создаём экземпляр класса EventConnections
EventConnections unstack_event_connections;

// связываем с этим экземпляром при подписке на событие (можно связывать подписки на разные события)
publisher->getEventUnstack().connect(unstack_event_connections, unstack_event_handler);

// другие подписки также связаны с этим экземпляром EventConnections
// (например, можно подписываться с помощью лямбда-функций)
publisher->getEventUnstack().connect(unstack_event_connections, []() {
		Log::message("\Обработка события Unstack (лямбда).\n");
	}
);

// ...

// позже все эти связанные подписки можно удалить одной строкой
unstack_event_connections.disconnectAll();

//////////////////////////////////////////////////////////////////////////////
//  2. Можно подписываться и отписываться через экземпляр класса EventConnection.
//  А также включать и отключать это конкретное соединение при необходимости.
//////////////////////////////////////////////////////////////////////////////

// создаём экземпляр класса EventConnection
EventConnection unstack_event_connection;

// подписываемся на событие Unstack с функцией-обработчиком, сохраняя соединение
publisher->getEventUnstack().connect(unstack_event_connection, unstack_event_handler);

// ...

// можно временно отключить конкретное соединение события для выполнения определённых действий
unstack_event_connection.setEnabled(false);

// ... выполняемые действия

// и снова включить его при необходимости
unstack_event_connection.setEnabled(true);

// ...

// удаляем подписку на событие Unstack через соединение
unstack_event_connection.disconnect();

//////////////////////////////////////////////////////////////////////////////
//  3. Можно добавить экземпляр EventConnection/EventConnections как член класса,
//  обрабатывающего событие. В этом случае все связанные подписки будут
//  автоматически удалены при вызове деструктора класса
//////////////////////////////////////////////////////////////////////////////

// Класс, обрабатывающий событие
class SomeClass
{
public:
	// экземпляр класса EventConnections как член класса
	EventConnections e_connections;

	// Обработчик события Unstack, реализованный как член класса
	void event_handler()
	{
		Log::message("\Обработка события Unstack\n");
		// ...
	}
};

SomeClass *sc = new SomeClass();

// ...

// указываем экземпляр класса, если метод-обработчик принадлежит какому-либо классу
publisher->getEventUnstack().connect(sc->e_connections, sc, &SomeClass::event_handler);

// ...

// экземпляр класса-обработчика удаляется, а все его подписки автоматически отменяются
delete sc;

//////////////////////////////////////////////////////////////////////////////
//   4. Подписка на событие с сохранением идентификатора соединения
//   и последующей отпиской по этому идентификатору
//////////////////////////////////////////////////////////////////////////////
// экземпляр класса EventConnections для управления соединениями событий
EventConnections e_connections;

// определяем идентификатор соединения, который будет использован для отписки позже
EventConnectionId unstack_handler_id;

// подписываемся на событие Unstack с лямбда-обработчиком, сохраняя идентификатор соединения
unstack_handler_id = publisher->getEventUnstack().connect(e_connections, []() {
		Log::message("\Обработка события Unstack (лямбда).\n");
	}
);

// удаляем подписку позже, используя идентификатор
publisher->getEventUnstack().disconnect(unstack_handler_id);

//////////////////////////////////////////////////////////////////////////////
//   5. Игнорирование всех событий Unstack при необходимости
//////////////////////////////////////////////////////////////////////////////

// можно временно отключить событие для выполнения определённых действий без его срабатывания
publisher->getEventUnstack().setEnabled(false);

// ... выполняемые действия

// и снова включить его при необходимости
publisher->getEventUnstack().setEnabled(true);
```

## Event<const Ptr < WindowEvent > &> getEventWindowEvent () const

Событие, срабатывающее при событии окна. Вы можете подписываться на события через *connect()* и отписываться через *disconnect()*. Также для удобства можно использовать классы *[EventConnection](../../../api/library/common/events/class.eventconnection_cpp.md)* и *[EventConnections](../../../api/library/common/events/class.eventconnections_cpp.md)* (см. примеры ниже).

> **Notice:** Подробнее см. статью [Event Handling](../../../code/fundamentals/events/index_cpp.md).

 Сигнатура обработчика события выглядит следующим образом: *myhandler(const Ptr<WindowEvent> & **event**)*
<details>
<summary>Показать пример | Скрыть</summary>

**Пример использования**

```cpp
// реализация обработчика события WindowEvent
void windowevent_event_handler(const Ptr<WindowEvent> & event)
{
	Log::message("\Обработка события WindowEvent\n");
}

//////////////////////////////////////////////////////////////////////////////
//  1. Несколько подписок можно связать с экземпляром класса EventConnections,
//  который затем можно использовать для отмены всех этих подписок сразу
//////////////////////////////////////////////////////////////////////////////

// создаём экземпляр класса EventConnections
EventConnections windowevent_event_connections;

// связываем с этим экземпляром при подписке на событие (можно связывать подписки на разные события)
publisher->getEventWindowEvent().connect(windowevent_event_connections, windowevent_event_handler);

// другие подписки также связаны с этим экземпляром EventConnections
// (например, можно подписываться с помощью лямбда-функций)
publisher->getEventWindowEvent().connect(windowevent_event_connections, [](const Ptr<WindowEvent> & event) {
		Log::message("\Обработка события WindowEvent (лямбда).\n");
	}
);

// ...

// позже все эти связанные подписки можно удалить одной строкой
windowevent_event_connections.disconnectAll();

//////////////////////////////////////////////////////////////////////////////
//  2. Можно подписываться и отписываться через экземпляр класса EventConnection.
//  А также включать и отключать это конкретное соединение при необходимости.
//////////////////////////////////////////////////////////////////////////////

// создаём экземпляр класса EventConnection
EventConnection windowevent_event_connection;

// подписываемся на событие WindowEvent с функцией-обработчиком, сохраняя соединение
publisher->getEventWindowEvent().connect(windowevent_event_connection, windowevent_event_handler);

// ...

// можно временно отключить конкретное соединение события для выполнения определённых действий
windowevent_event_connection.setEnabled(false);

// ... выполняемые действия

// и снова включить его при необходимости
windowevent_event_connection.setEnabled(true);

// ...

// удаляем подписку на событие WindowEvent через соединение
windowevent_event_connection.disconnect();

//////////////////////////////////////////////////////////////////////////////
//  3. Можно добавить экземпляр EventConnection/EventConnections как член класса,
//  обрабатывающего событие. В этом случае все связанные подписки будут
//  автоматически удалены при вызове деструктора класса
//////////////////////////////////////////////////////////////////////////////

// Класс, обрабатывающий событие
class SomeClass
{
public:
	// экземпляр класса EventConnections как член класса
	EventConnections e_connections;

	// Обработчик события WindowEvent, реализованный как член класса
	void event_handler(const Ptr<WindowEvent> & event)
	{
		Log::message("\Обработка события WindowEvent\n");
		// ...
	}
};

SomeClass *sc = new SomeClass();

// ...

// указываем экземпляр класса, если метод-обработчик принадлежит какому-либо классу
publisher->getEventWindowEvent().connect(sc->e_connections, sc, &SomeClass::event_handler);

// ...

// экземпляр класса-обработчика удаляется, а все его подписки автоматически отменяются
delete sc;

//////////////////////////////////////////////////////////////////////////////
//   4. Подписка на событие с сохранением идентификатора соединения
//   и последующей отпиской по этому идентификатору
//////////////////////////////////////////////////////////////////////////////
// экземпляр класса EventConnections для управления соединениями событий
EventConnections e_connections;

// определяем идентификатор соединения, который будет использован для отписки позже
EventConnectionId windowevent_handler_id;

// подписываемся на событие WindowEvent с лямбда-обработчиком, сохраняя идентификатор соединения
windowevent_handler_id = publisher->getEventWindowEvent().connect(e_connections, [](const Ptr<WindowEvent> & event) {
		Log::message("\Обработка события WindowEvent (лямбда).\n");
	}
);

// удаляем подписку позже, используя идентификатор
publisher->getEventWindowEvent().disconnect(windowevent_handler_id);

//////////////////////////////////////////////////////////////////////////////
//   5. Игнорирование всех событий WindowEvent при необходимости
//////////////////////////////////////////////////////////////////////////////

// можно временно отключить событие для выполнения определённых действий без его срабатывания
publisher->getEventWindowEvent().setEnabled(false);

// ... выполняемые действия

// и снова включить его при необходимости
publisher->getEventWindowEvent().setEnabled(true);

```
