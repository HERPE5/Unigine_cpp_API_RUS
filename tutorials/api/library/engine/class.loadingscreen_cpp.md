# Класс Unigine.LoadingScreen (CPP)

**Заголовочный файл:** #include <UnigineLoadingScreen.h>

> **Примечание:** Этот класс является одиночкой (singleton).


Одиночка, управляющий настройками [loading screen](../../../code/gui/screens/index.md#loading). Его демонстрация даёт UNIGINE время на загрузку всех узлов и ресурсов мира. При необходимости вы также можете показывать собственный экран загрузки.


Экран загрузки отображает [texture](../../../code/gui/skin/index.md#splash), которая обычно разделена на две части, расположенные вертикально друг над другом — начальное и конечное изображения — которые постепенно смешиваются от начала до конца загрузки, чтобы показывать прогресс. Смешивание выполняется на основе альфа-канала нижней (финальной) части текстуры, поэтому с помощью альфа-канала можно создать псевдоанимацию: области нижней половины с малыми значениями альфа будут показаны первыми, области с большими значениями альфа — последними.

### Пример


Пример кода того, как добавить собственные экраны загрузки для загрузки приложения и мира.


Чтобы показать ваш экран загрузки при инициализации системной логики до загрузки мира, определите его внутри метода *init()* [System Logic](../../../code/fundamentals/execution_sequence/app_logic_system.md#systemlogic):


```cpp
#include "AppSystemLogic.h"
#include "UnigineLoadingScreen.h"

using namespace Unigine;

int AppSystemLogic::init()
{


	// задаём новую трансформацию для текстуры экрана загрузки
	Math::vec4 transform = Math::vec4(1.0f, 1.0f, 0.0f, 0.0f);

	// включаем экран загрузки
	LoadingScreen::setEnabled(true);

	// применяем трансформацию к текстуре экрана загрузки
	LoadingScreen::setTransform(transform);

	Math::ivec2 winsize = WindowManager::getMainWindow()->getClientSize();
	// вычисляем соотношение сторон, чтобы показать соответствующую текстуру
	float aspect_ratio = (float)winsize.x / (float)winsize.y;

	// если соотношение сторон 4:3, показываем следующий экран загрузки
	// во время загрузки мира
	if (aspect_ratio < 1.5f) {
		LoadingScreen::setTexturePath("textures/splash_4x3.png");
	}
	else {
		// если соотношение сторон 16:9, показываем этот экран загрузки
		// во время загрузки мира
		LoadingScreen::setTexturePath("textures/splash_16x9.png");
	}
	// задаём текст, отображаемый на экране загрузки,
	// с определённым смещением по осям X и Y
	LoadingScreen::setText("<xy x=\"%50\" dx=\"0\" y=\"%50\" dy=\"0\"/>LOADING_PROGRESS");

	// задаём продолжительность (в миллисекундах) и отображаем экран загрузки при загрузке мира
	float duration = 5000.0f;
	float begin = clock();

	while (clock() - begin < duration)
		LoadingScreen::render((clock() - begin) / duration * 100.0f);

	// отключаем экран загрузки
	LoadingScreen::setEnabled(false);

	return 1;
}


```


Экран загрузки, определённый в методе *init()* [World Logic](../../../code/fundamentals/execution_sequence/app_logic_system.md#worldlogic), будет показан сразу после загрузки мира:


```cpp
#include "AppWorldLogic.h"
#include "UnigineLoadingScreen.h"

using namespace Unigine;

int AppWorldLogic::init()
{

	// включаем экран загрузки
	LoadingScreen::setEnabled(true);


	// задаём текст, отображаемый на экране загрузки,
	// указывая цвет, шрифт и определённое смещение по осям X и Y
	LoadingScreen::setText("<p align=\"center\"><font size=\"20\" color=\"#FF0000FF\">CUSTOM LOADING TEXT</font></p>");

	// задаём продолжительность (в миллисекундах) и отображаем экран загрузки при загрузке мира
	float duration = 5000.0f;
	float begin = clock();

	while (clock() - begin < duration)
		LoadingScreen::render((clock() - begin) / duration * 100.0f);

	// отключаем экран загрузки
	LoadingScreen::setEnabled(false);

	return 1;
}


```

## void setEnabled ( bool enabled )

Устанавливает новое значение, указывающее, разрешён ли ручной рендеринг экрана загрузки.

- *bool* **enabled** - **true** — включить рендеринг экрана загрузки; **false** — отключить.

## bool isEnabled () const

## static Event<> getEventRenderEnd () const

Событие, срабатывающее по завершении рендеринга экрана загрузки. Эта функция полезна, например, при реализации пользовательской функции рендеринга экрана загрузки. Обработчик события не должен принимать аргументов. Вы можете подписываться на события через *connect()* и отписываться через *disconnect()*. Также для удобства можно использовать классы *[EventConnection](../../../api/library/common/events/class.eventconnection_cpp.md)* и *[EventConnections](../../../api/library/common/events/class.eventconnections_cpp.md)* (см. примеры ниже).

> **Notice:** Подробнее см. статью [Event Handling](../../../code/fundamentals/events/index_cpp.md).

 Сигнатура обработчика события выглядит следующим образом: *myhandler()*

**Пример использования**

```cpp
// реализация обработчика события RenderEnd
void renderend_event_handler()
{
	Log::message("\Обработка события RenderEnd\n");
}

//////////////////////////////////////////////////////////////////////////////
//  1. Несколько подписок можно связать с экземпляром класса EventConnections,
//  который затем можно использовать для отмены всех этих подписок сразу
//////////////////////////////////////////////////////////////////////////////

// создаём экземпляр класса EventConnections
EventConnections renderend_event_connections;

// связываем с этим экземпляром при подписке на событие (можно связывать подписки на разные события)
LoadingScreen::getEventRenderEnd().connect(renderend_event_connections, renderend_event_handler);

// другие подписки также связаны с этим экземпляром EventConnections
// (например, можно подписываться с помощью лямбда-функций)
LoadingScreen::getEventRenderEnd().connect(renderend_event_connections, []() {
		Log::message("\Обработка события RenderEnd (лямбда).\n");
	}
);

// ...

// позже все эти связанные подписки можно удалить одной строкой
renderend_event_connections.disconnectAll();

//////////////////////////////////////////////////////////////////////////////
//  2. Можно подписываться и отписываться через экземпляр класса EventConnection.
//  А также включать и отключать это конкретное соединение при необходимости.
//////////////////////////////////////////////////////////////////////////////

// создаём экземпляр класса EventConnection
EventConnection renderend_event_connection;

// подписываемся на событие RenderEnd с функцией-обработчиком, сохраняя соединение
LoadingScreen::getEventRenderEnd().connect(renderend_event_connection, renderend_event_handler);

// ...

// можно временно отключить конкретное соединение события для выполнения определённых действий
renderend_event_connection.setEnabled(false);

// ... выполняемые действия

// и снова включить его при необходимости
renderend_event_connection.setEnabled(true);

// ...

// удаляем подписку на событие RenderEnd через соединение
renderend_event_connection.disconnect();

//////////////////////////////////////////////////////////////////////////////
//  3. Можно добавить экземпляр EventConnection/EventConnections как член класса,
//  обрабатывающего событие. В этом случае все связанные подписки будут
//  автоматически удалены при вызове деструктора класса
//////////////////////////////////////////////////////////////////////////////

// Класс, обрабатывающий событие
class SomeClass
{
public:
	// экземпляр класса EventConnections как член класса
	EventConnections e_connections;

	// Обработчик события RenderEnd, реализованный как член класса
	void event_handler()
	{
		Log::message("\Обработка события RenderEnd\n");
		// ...
	}
};

SomeClass *sc = new SomeClass();

// ...

// указываем экземпляр класса, если метод-обработчик принадлежит какому-либо классу
LoadingScreen::getEventRenderEnd().connect(sc->e_connections, sc, &SomeClass::event_handler);

// ...

// экземпляр класса-обработчика удаляется, а все его подписки автоматически отменяются
delete sc;

//////////////////////////////////////////////////////////////////////////////
//   4. Подписка на событие с сохранением идентификатора соединения
//   и последующей отпиской по этому идентификатору
//////////////////////////////////////////////////////////////////////////////
// экземпляр класса EventConnections для управления соединениями событий
EventConnections e_connections;

// определяем идентификатор соединения, который будет использован для отписки позже
EventConnectionId renderend_handler_id;

// подписываемся на событие RenderEnd с лямбда-обработчиком, сохраняя идентификатор соединения
renderend_handler_id = LoadingScreen::getEventRenderEnd().connect(e_connections, []() {
		Log::message("\Обработка события RenderEnd (лямбда).\n");
	}
);

// удаляем подписку позже, используя идентификатор
LoadingScreen::getEventRenderEnd().disconnect(renderend_handler_id);

//////////////////////////////////////////////////////////////////////////////
//   5. Игнорирование всех событий RenderEnd при необходимости
//////////////////////////////////////////////////////////////////////////////

// можно временно отключить событие для выполнения определённых действий без его срабатывания
LoadingScreen::getEventRenderEnd().setEnabled(false);

// ... выполняемые действия

// и снова включить его при необходимости
LoadingScreen::getEventRenderEnd().setEnabled(true);
```

## void render ( int progress )

Рендерит пользовательский экран загрузки в заданном состоянии прогресса. Используйте эту функцию в цикле для создания постепенного перехода между начальным (верхняя непрозрачная часть) и конечным (нижняя прозрачная часть) состояниями текстуры экрана загрузки.
### Аргументы

- *int* **progress** - Прогресс альфа-смешивания между 2 экранами, хранящимися в текстуре. Значение в диапазоне **[0;100]** задаёт порог альфа-канала, согласно которому рендерятся пиксели из *начального* (непрозрачного) или *конечного* (прозрачного) экрана в текстуре. При значении **0** загружается начальный экран. При значении **100** загружается конечный экран.

## void render ( int progress , const char * message )

Рендерит пользовательский экран загрузки в заданном состоянии прогресса и выводит заданное сообщение. Используйте эту функцию в цикле для создания постепенного перехода между начальным (верхняя непрозрачная часть) и конечным (нижняя прозрачная часть) состояниями текстуры экрана загрузки, одновременно выводя пользовательскую стадию загрузки.
### Аргументы

- *int* **progress** - Прогресс альфа-смешивания между 2 экранами загрузки, хранящимися в текстуре. Значение в диапазоне **[0;100]** задаёт порог альфа-канала, согласно которому рендерятся пиксели из *начального* (непрозрачного) или *конечного* (прозрачного) экрана загрузки в текстуре. При значении **0** загружается начальный экран. При значении **100** загружается конечный экран.
- *const char ** **message** - Выводимое сообщение, представляющее стадию загрузки.
