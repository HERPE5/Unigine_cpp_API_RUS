# Класс Unigine::ProfilerDump (CPP)

**Заголовочный файл:** #include <UnigineProfiler.h>


Класс **ProfilerDump** предоставляет доступ к данным о производительности, хранящимся в [profiler dump files](../../../tools/profiling/profiler_dump/index_cpp.md) (`*.profiler_dump`). Дампы профайлера сохраняются в бинарном формате для уменьшения размера файла и ускорения записи. Из-за этого файл нельзя просмотреть напрямую в текстовом редакторе — его нужно открывать с помощью этого класса или инструмента [Profiler Reader](../../../tools/profiling/profiler_reader_tool/index.md).


Важно понимать, как правильно извлекать информацию из дампа, чтобы избежать повреждения данных или получения некорректных результатов.


- При работе с консольными переменными всегда проверяйте их тип с помощью *[getConsoleVariableType()](../../...md#getConsoleVariableType_int_int)*, прежде чем читать их значение. Вызов метода *getConsoleVariableValue**** или *getConsoleVariableHistoryValue**** для переменной другого типа автоматически выполняет приведение типа; если преобразование не удаётся, возвращается значение по умолчанию (пустое или нулевое) для этого типа. Приведённый ниже пример кода иллюстрирует, как правильно извлечь все консольные переменные и их историю из дампа и вывести их в консоль. <details> <summary>Разбор консольных переменных</summary> ```cpp ProfilerDumpPtr dump = ProfilerDump::create(); dump->load("path_to_your_profiler_dump_file"); for (int i = 0; i < dump->getNumConsoleVariables(); i++) { int type = dump->getConsoleVariableType(i); String name = dump->getConsoleVariableName(i); Log::message("Console variable %s: ", name.get()); switch (type) { case ProfilerDump::DUMP_CONSOLE_VARIABLE_TYPE_STRING: Log::message("%s ", dump->getConsoleVariableValueString(i)); break; case ProfilerDump::DUMP_CONSOLE_VARIABLE_TYPE_INT: Log::message("%d ", dump->getConsoleVariableValueInt(i)); break; case ProfilerDump::DUMP_CONSOLE_VARIABLE_TYPE_FLOAT: Log::message("%f ", dump->getConsoleVariableValueFloat(i)); break; case ProfilerDump::DUMP_CONSOLE_VARIABLE_TYPE_VEC2: { Math::vec2 v = dump->getConsoleVariableValueVec2(i); Log::message("(%g, %g) ", v.x, v.y); break; } case ProfilerDump::DUMP_CONSOLE_VARIABLE_TYPE_VEC3: { Math::vec3 v = dump->getConsoleVariableValueVec3(i); Log::message("(%g, %g, %g) ", v.x, v.y, v.z); break; } case ProfilerDump::DUMP_CONSOLE_VARIABLE_TYPE_VEC4: { Math::vec4 v = dump->getConsoleVariableValueVec4(i); Log::message("(%g, %g, %g, %g) ", v.x, v.y, v.z, v.w); break; } case ProfilerDump::DUMP_CONSOLE_VARIABLE_TYPE_PALETTE: Log::message("%s ", dump->getConsoleVariableValuePalette(i).toString().get()); break; default: break; } int num_history = dump->getNumConsoleVariableHistory(i); for (int h = 0; h < num_history; h++) { if (h == 0) { Log::message(" ["); Log::message("%d: ", dump->getConsoleVariableHistoryFrame(i, h)); } else { Log::message("%d: ", dump->getConsoleVariableHistoryFrame(i, h)); } switch (type) { case ProfilerDump::DUMP_CONSOLE_VARIABLE_TYPE_STRING: Log::message("%s, ", dump->getConsoleVariableHistoryValueString(i, h)); break; case ProfilerDump::DUMP_CONSOLE_VARIABLE_TYPE_INT: Log::message("%d, ", dump->getConsoleVariableHistoryValueInt(i, h)); break; case ProfilerDump::DUMP_CONSOLE_VARIABLE_TYPE_FLOAT: Log::message("%f, ", dump->getConsoleVariableHistoryValueFloat(i, h)); break; case ProfilerDump::DUMP_CONSOLE_VARIABLE_TYPE_VEC2: { Math::vec2 v = dump->getConsoleVariableValueVec2(i); Log::message("(%g, %g) ", v.x, v.y); break; } case ProfilerDump::DUMP_CONSOLE_VARIABLE_TYPE_VEC3: { Math::vec3 v = dump->getConsoleVariableValueVec3(i); Log::message("(%g, %g, %g) ", v.x, v.y, v.z); break; } case ProfilerDump::DUMP_CONSOLE_VARIABLE_TYPE_VEC4: { Math::vec4 v = dump->getConsoleVariableValueVec4(i); Log::message("(%g, %g, %g, %g) ", v.x, v.y, v.z, v.w); break; } case ProfilerDump::DUMP_CONSOLE_VARIABLE_TYPE_PALETTE: Log::message("%s, ", dump->getConsoleVariableHistoryValuePalette(i, h).toString().get()); break; default: break; } } if (num_history > 0) Log::message("]\n"); else Log::message("\n"); } ``` </details>
- При чтении параметров профайлера (метрик) важно понимать, [how per-frame parameter values are stored](../../../tools/profiling/profiler_dump/index_cpp.md#profiler_dump_values). Каждая метрика **может существовать только для определённых кадров**, в зависимости от того, была ли она активна на момент записи. Поскольку значения параметров хранятся в объединённой (union) памяти (для уменьшения размера файла), использование неверного метода-геттера (например, попытка получить значение *int* из параметра типа *float*) вернёт некорректные данные. Поэтому лучше проверять тип параметра перед чтением значений. Приведённый ниже пример кода иллюстрирует, как правильно извлечь все метрики профилирования из дампа и вывести их в консоль. <details> <summary>Разбор параметров профайлера</summary> ```cpp ProfilerDumpPtr dump = ProfilerDump::create(); dump->load("path_to_your_profiler_dump_file"); for (int p = 0; p < dump->getNumDumpParameters(); p++) { int type = dump->getDumpParameterType(p); String name = dump->getDumpParameterName(p); if (type == ProfilerDump::DUMP_PARAMETER_TYPE_INT) { Log::message("%s: Min: %d, Max: %d, Avg: %d [", name.get(), dump->getDumpParameterIntMin(p), dump->getDumpParameterIntMax(p), dump->getDumpParameterIntAvg(p) ); for (int frame = 0; frame < dump->getNumFrames(); frame++) { if (dump->containsFrameParameterIndex(frame, p)) Log::message("%d, ", dump->getFrameParameterValueInt(frame, p)); else Log::message("NAN, "); } } else { Log::message("%s: Min: %f, Max: %f, Avg: %f [", name.get(), dump->getDumpParameterFloatMin(p), dump->getDumpParameterFloatMax(p), dump->getDumpParameterFloatAvg(p) ); for (int frame = 0; frame < dump->getNumFrames(); frame++) { if (dump->containsFrameParameterIndex(frame, p)) Log::message("%f, ", dump->getFrameParameterValueFloat(frame, p)); else Log::message("NAN, "); } } Log::message("]\n"); } ``` </details>

## ProfilerDump ( )

Конструктор по умолчанию. Создаёт пустой экземпляр **ProfilerDump**, который впоследствии можно инициализировать, загрузив файл дампа профайлера (с расширением `*.profiler_dump`) с помощью метода *[load()](../../...md#load_cstr_int)* или *[info()](../../...md#info_cstr_int)*.
## bool load ( const char * path )

Загружает все данные дампа профайлера из указанного файла. Этот метод читает и разбирает файл `*.profiler_dump`, предоставляя доступ ко всей записанной информации профилирования через API класса **ProfilerDump**.
### Аргументы

- *const char ** **path** - Путь к файлу дампа профайлера.

### Возвращаемое значение

true, если файл дампа был успешно загружен и разобран; иначе false.
## bool info ( const char * path )

Загружает данные дампа профайлера из указанного файла, **за исключением поkадровой информации**. Этот метод читает и разбирает файл `*.profiler_dump`, предоставляя доступ к системной информации, консольным переменным и общей статистике параметров через API класса **ProfilerDump**.
### Аргументы

- *const char ** **path** - Путь к файлу дампа профайлера.

### Возвращаемое значение

true, если файл дампа был успешно загружен и разобран; иначе false.
