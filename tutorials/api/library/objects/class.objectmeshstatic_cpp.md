# ObjectMeshStatic Class (CPP)

**Header:** #include <UnigineObjects.h>

**Inherits from:** Object


Этот класс используется для работы со [static meshes](../../../objects/objects/mesh/index.md).


Статический меш представляет собой недеформируемый набор вершин, рёбер и треугольников, определяющих геометрию объекта. По умолчанию его геометрия фиксирована во время выполнения и может быть трансформирована только целиком (перемещена, повёрнута, масштабирована). Однако ***ObjectMeshStatic*** поддерживает опциональные процедурные режимы, позволяющие [modify or generate](#procedural_workflow) данные меша во время выполнения через код.


**[ObjectMeshDynamic](../../../api/library/objects/class.objectmeshdynamic_cpp.md)** также обеспечивает процедурные изменения геометрии, но **ObjectMeshStatic** предоставляет большую гибкость в управлении скоростью генерации и использованием памяти. Подробнее см. в разделе [Procedural Mesh Workflow](#procedural_workflow).


### Const Meshes


UNIGINE использует типы умных указателей для управления процедурными данными меша в ***ObjectMeshStatic*** и других связанных классах (***[ObjectGuiMesh](../../../api/library/objects/class.objectguimesh_cpp.md)***, ***[DecalMesh](../../../api/library/decals/class.decalmesh_cpp.md)***, ***[ObjectMeshCluster](../../../api/library/objects/class.objectmeshcluster_cpp.md)***, ***[ObjectMeshClutter](../../../api/library/objects/class.objectmeshclutter_cpp.md)***). В частности, движок различает ***MeshPtr*** (модифицируемый указатель на меш) и ***ConstMeshPtr*** (указатель на меш только для чтения). Некоторые методы, например *[getMeshCurrentRAM()](#getMeshCurrentRAM_ConstMesh)*, возвращают ***ConstMeshPtr***, чтобы гарантировать, что возвращаемый меш нельзя модифицировать напрямую.


Это позволяет предоставлять данные меша для инспекции, защищая их при этом от непреднамеренных изменений:


```cpp
Ptr<ConstMesh> mesh = object->getMeshCurrentRAM();
mesh.addSurface("new_surface");				// Ошибка! Нельзя модифицировать через ConstMeshPtr

Ptr<Mesh> editable_mesh = object->getMeshDynamicRAM();
editable_mesh.addSurface("new_surface"); 	// Успех! Меш модифицирован

```


### Процедурный рабочий процесс меша


Статические меши поддерживают [streaming](../../../principles/data_streaming/index.md), позволяющий загружать геометрию с диска по требованию для снижения использования памяти. Однако при включенном процедурном режиме поведение стриминга изменяется в зависимости от [selected mode](#PROCEDURAL_MODE): некоторые режимы удерживают все данные в RAM или VRAM, в то время как другие допускают доступ на основе диска. Эти различия напрямую влияют на производительность и потребление памяти во время выполнения.


При создании процедурной геометрии типичный рабочий процесс выглядит следующим образом:


1. **Создание или загрузка меша.** Перед работой с процедурной геометрией сначала [create an object](#ObjectMeshStatic_class), который получит сгенерированный меш. Затем начните с создания меша с помощью API *[Mesh](../../../api/library/rendering/class.mesh_cpp.md)* или загрузите существующий с диска. Вы можете полностью определить геометрию в коде (вершины, индексы, поверхности и т.д.) или повторно использовать подготовленные ассеты в качестве входных данных.
2. **Включение процедурного режима.** Вызовите *[setMeshProceduralMode](#setMeshProceduralMode_int_int_void)*, чтобы включить модификацию во время выполнения. Геометрию нельзя изменить, пока не выбран один из процедурных режимов. > **Notice:** Каждый процедурный режим имеет особое поведение относительно того, как геометрия хранится и как к ней осуществляется доступ (в RAM, VRAM или файле). Подробности о том, как каждый режим обрабатывает память, стриминг и производительность, см. в описаниях *[PROCEDURAL_MODE](#PROCEDURAL_MODE)*.
3. **Генерация и применение геометрии.** Существует два основных подхода к обновлению процедурных данных меша: > **Notice:** Если меш предназначен для участия в проверках столкновений и пересечений, вы **должны явно вызвать** **[createCollisionData()](../../../api/library/rendering/class.mesh_cpp.md#createCollisionData_int_int_void)** (или только **[createSpatialTree()](../../../api/library/rendering/class.mesh_cpp.md#createSpatialTree_int_void)** для пересечений, либо **[createEdges()](../../../api/library/rendering/class.mesh_cpp.md#createEdges_int_void)** для столкновений) после изменения данных меша и перед вызовом любых методов *apply*. Это гарантирует, что необходимые внутренние структуры данных (например, рёбра и пространственное дерево) сгенерированы и актуальны. > > > Учтите, что генерация этих структур может быть затратной по времени и памяти. Если сгенерированный меш используется исключительно в визуальных целях, создавать их не требуется, и это может значительно ускорить процесс генерации.

  - **Использование упрощенного API генерации.** Для типовых процедурных рабочих процессов методы *[runGenerateMeshProceduralAsync()](#runGenerateMeshProceduralAsync_GenerateMeshProcedural_int_int)* и *[runGenerateMeshProceduralForce()](#runGenerateMeshProceduralForce_GenerateMeshProcedural_int_int)* позволяют планировать генерацию меша через callback-функции. В вашем callback вы определяете, как строится геометрия (заполняете *[Mesh](../../../api/library/rendering/class.mesh_cpp.md)*), а движок применит её автоматически. > **Notice:** В случае частой асинхронной генерации рекомендуется использовать *[isMeshProceduralDone()](../../...md#isMeshProceduralDone_int)* и *[isMeshProceduralActive()](../../...md#isMeshProceduralActive_int)* для проверки текущего состояния меша и координации обновлений, что предотвращает состояния гонки и обеспечивает детерминированные результаты.
  - **Ручное управление обновлением геометрии.** Вы также можете применять данные меша напрямую, используя набор методов, различающихся стратегией обновления. Все они служат одной и той же цели: заменить текущий меш новыми данными. API процедурной генерации предоставляет большую гибкость и контроль над тем, как применяется новая геометрия, с различиями, закодированными в именах методов: > **Notice:** Если имя метода содержит один из этих терминов, оно отражает то, как передаются данные меша и когда выполняется операция. Выберите метод, соответствующий вашим потребностям, например используйте *[applyCopyMeshProceduralForce()](#applyCopyMeshProceduralForce_ConstMesh_int_int)* для **немедленного копирования**, либо *[applyMoveMeshProceduralAsync()](#applyMoveMeshProceduralAsync_Mesh_int_int)* для **передачи** данных **без блокировки** главного потока.

    - **copy**: Данные меша копируются во внутреннюю память объекта. **Заданный меш остается неизменным**. Это может быть полезно при повторном использовании одной и той же геометрии для нескольких объектов.
    - **move**: Данные меша передаются в объект без копирования памяти. Операция обменивает данные меша между объектом и заданным мешом, поэтому **заданный меш больше не содержит своих исходных данных вершин**, и его содержимое заменяется. Это позволяет избежать затрат на операции копирования и обеспечивает более быстрые обновления.
    - **force**: Операция выполняется немедленно в главном потоке. Полезно для обновлений в реальном времени, когда задержка недопустима. В режиме *[PROCEDURAL_MODE_DYNAMIC](#PROCEDURAL_MODE_DYNAMIC)* принудительное перемещение ведёт себя идентично своему асинхронному варианту.
    - **async**: Позволяет избежать блокировки главного потока и особенно полезно в режимах *[PROCEDURAL_MODE_FILE](#PROCEDURAL_MODE_FILE)* или *[PROCEDURAL_MODE_BLOB](#PROCEDURAL_MODE_BLOB)*, где дисковый ввод-вывод или потоковая передача данных из памяти могут быть вынесены в фоновый режим.

## ObjectMeshStatic Class

### Перечисления

## LIGHTMAP_QUALITY

Пресет качества запекания карты освещения, который нужно использовать.
| Name | Description |
|---|---|
| **LIGHTMAP_QUALITY_GLOBAL** = 0 | Глобальный пресет качества, заданный в настройках [Bake Lighting](../../../editor2/lighting/gi/bake_lighting/index.md#lightmaps). |
| **LIGHTMAP_QUALITY_DRAFT** = 1 | Черновой пресет качества карт освещения. |
| **LIGHTMAP_QUALITY_LOW** = 2 | Низкий пресет качества карт освещения. |
| **LIGHTMAP_QUALITY_MEDIUM** = 3 | Средний пресет качества карт освещения. |
| **LIGHTMAP_QUALITY_HIGH** = 4 | Высокий пресет качества карт освещения. |
| **LIGHTMAP_QUALITY_ULTRA** = 5 | Максимально высокий пресет качества карт освещения. |

## LIGHTMAP_MODE

Режим карты освещения, определяющий источник используемой текстуры карты освещения.
| Name | Description |
|---|---|
| **LIGHTMAP_MODE_UNIQUE** = 0 | Запечь уникальную текстуру карты освещения для поверхности. |
| **LIGHTMAP_MODE_CUSTOM** = 1 | Использовать пользовательскую текстуру карты освещения для поверхности. |
| **LIGHTMAP_MODE_SURFACE** = 2 | Повторно использовать уже запечённую текстуру карты освещения с другой поверхности. Может использоваться для LOD-ов. |

## SURFACE_CUSTOM_TEXTURE_MODE

Режим, определяющий источник пользовательской текстуры поверхности, который нужно использовать.
| Name | Description |
|---|---|
| **SURFACE_CUSTOM_TEXTURE_MODE_UNIQUE** = 0 | Использовать уникальную пользовательскую текстуру для поверхности. |
| **SURFACE_CUSTOM_TEXTURE_MODE_SURFACE** = 1 | Использовать пользовательскую текстуру с другой поверхности. Этот параметр предназначен для использования с LOD-ами, имеющими одинаковые UV-карты. |

## PROCEDURAL_MODE

| Name | Description |
|---|---|
| **PROCEDURAL_MODE_DISABLE** = 0 | Отключает процедурный режим. Процедурные данные не хранятся и не управляются. |
| **PROCEDURAL_MODE_DYNAMIC** = 1 | Этот режим оптимизирован для высокоскоростных динамических модификаций. Обеспечивает наивысшую производительность, но с наибольшим использованием RAM и VRAM. Меши не выгружаются автоматически, требуется ручная очистка памяти с помощью **[deleteDynamicMesh()](../../...md#deleteDynamicMesh_int)**. Если меш стримится во время модификации, это может привести к сбою. > **Notice:** Этот режим предназначен **только для небольшого числа легковесных объектов**, которые обновляются очень часто. |
| **PROCEDURAL_MODE_FILE** = 2 | В этом режиме процедурные данные меша хранятся в виде временных файлов на диске. Каждый раз при изменении процедурного меша соответствующий файл обновляется. Это позволяет движку выгружать как RAM, так и VRAM при необходимости, ценой немного более низкой производительности из-за операций дискового ввода-вывода. Конфигурация доступна через **[`*.boot`](../../../code/configuration_file_cpp.md)** или *[Console](../../../code/console/index.md)*, но вступает в силу только при запуске движка: - *mesh_procedural_path*: определяет путь, где хранятся временные процедурные файлы. - *mesh_procedural_read_only*: отключает запись на диск. > **Notice:** Отключение процедурного режима для меша приведёт к удалению соответствующего файла. > > > Когда несколько экземпляров движка используют один и тот же *mesh_procedural_path*, один экземпляр может удалить файлы, которые всё ещё используются другим. |
| **PROCEDURAL_MODE_BLOB** = 3 | В этом режиме все процедурные данные хранятся в памяти в виде временного *[Blob](../../../api/library/common/class.blob_cpp.md)*. VRAM и RAM загружаются непосредственно из этого Blob, который движок может выгружать при необходимости самостоятельно. Модификации выполняются быстрее по сравнению с режимом *FILE*, но ценой увеличенного использования RAM. Рендерящиеся (видимые) меши хранятся без сжатия для оптимальной производительности, в то время как невидимые меши сжимаются для экономии памяти. |

## bool applyMoveMeshProceduralForce ( const Ptr < Mesh > & mesh , int mesh_render_flags = 0 )

**[ Main Thread ]**
Принудительно перемещает все данные вершин из заданного меша в процедурный меш объекта, выполняя операцию немедленно без выделения памяти и копирования данных (семантика перемещения). Работает только когда **включен процедурный режим**.
